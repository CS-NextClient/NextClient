# Доказательства Linux x86 ABI GoldSrc

[English version](goldsrc-abi-linux-facts.md)

Linux supplement [facts_linux.json](../nextclient/goldsrc_abi/tools/facts_linux.json)
содержит независимые измерения штатного 32-разрядного Linux ABI, связанного со
сборкой движка 8684. Владение объявлениями описано в
[справочнике сопровождения](goldsrc-abi.ru.md). Закрепленные Windows-факты и
идентификаторы исходных координат сохраняются в
[facts.json](../nextclient/goldsrc_abi/tools/facts.json).

## Источники доказательств

Extraction inputs соответствуют оригинальной ревизии NextClient
`a64b71ecbbe10d7f0d601c3e210e98ef2ace2550`, ревизии NitroApi
`669639de5e998cf35c32bcaa121e2c57e284930b` и ревизии SDK
`e3130f351307968101ae569f609ce2c2d4b8eb3e`. Их исходные пути, включая
`dep/NclNitroApi/dep/ncl-hl1-source-sdk`, идентифицируют закрепленные записи.
Извлечение использует копии из соответствующих Git объектов, без изменения
рабочего SDK и без использования replacement declarations как эталона layout.

Два штатных бинарника предоставляют независимые ELF32-i386 DWARF данные:

| Бинарник | SHA256 |
|---|---|
| `hw.so` | `1e775773292407106ac17c98bc19f0444e8f1525d46e592de5cc53afad2b89e1` |
| `cstrike/cl_dlls/client.so` | `40283f3e0c4b6bd21f9281304957ab93c04c60ce5f3d2794cdaf58b3c11ab798` |

Статический анализ устанавливает сборку движка 8684. Функция `build_number` по
виртуальному адресу `0x000f4e80` читает глобальную переменную `date` по адресу
`0x002d53b0`; сохраненный указатель указывает на `Aug  3 2020` по адресу
`0x0026b810`. Начальный год 1901, множитель 365.25, усечение, индекс дня,
поправка високосного года и вычитание `0x88b3`, установленные дизассемблированием,
дают 8684. Бинарник клиента взят из той же установленной Steam-копии; его
идентичность закреплена отдельным хешем. Во время извлечения игра не запускалась.

GNU Binutils 2.42 извлекает DWARF. GCC 15.2.0 измеряет оригинальные полные
объявления с `-m32 -std=c++23`; Clang 22.1.3 независимо проверяет эти измерения
с `--target=i686-pc-linux-gnu -m32 -std=c++23` и существующим Linux sysroot.
Явные проверки целевой платформы охватывают четырехбайтовые указатели и
четырехбайтовый `wchar_t`. Supplement содержит фактические массивы команд,
параметры компиляторов, идентификаторы проб и результаты.

Сырые inputs, пробы с исходным кодом, DWARF dumps и диагностика сохраняются в
`build/abi-evidence/linux/`. Автор объявлений использует supplement и этот
справочник. Входные данные переносимости, предназначенные только для извлечения,
подключают существующие сетевые заголовки Linux и выбирают скалярные псевдонимы
SDK через `GNUC` и `NO_HLSDK_ARCHTYPES`. Оригинальные объявления записей не
изменяются.
Копия `com_model.h` для извлечения пропускает повторное объявление `cache_user_s`;
то же закрепленное определение предоставляется `quakedef.h`, ни одна
обязательная запись не изменяется. Байты всех оригинальных inputs сверяются
с закрепленными архивами.

## Охват и согласование источников

Обязательное замыкание содержит 117 материализованных записей верхнего уровня и
пять вложенных записей. Для полных и префиксных форм устанавливаются полный
Linux-размер, выравнивание, размещение баз и измерения полей. Совпадение Windows
и Linux layout также требует явной Linux-записи. Opaque storage префикса
резервирует полную штатную запись, включая нераскрытые поля.

| Запись | Linux-размер | Linux-выравнивание |
|---|---:|---:|
| `hud_player_info_t` | 28 | 4 |
| `CHud` | 27508 | 4 |
| `CHudMessage` | 16744 | 4 |
| `server_t` | 287756 | 4 |
| `server_static_t` | 132 | 4 |

Штатные DWARF данные соответствуют 121 обязательному идентификатору записи.
Сохраненная запись NitroApi `EngineMsg` устанавливается по закрепленному
оригинальному input и проверяется обоими компиляторами. DWARF предоставляет
полные opaque-размеры; полные оригинальные пробы и независимые проверки
компилятором устанавливают выравнивание и подтверждают смещения. DWARF2 не
содержит явного атрибута выравнивания этих штатных записей.

Выбор бинарника-владельца разрешает внутренние варианты. `player_info_t`
является записью движка, используемой `client_state_t::players`; ее измеренный
размер в `hw.so` равен 592. `playermove_t` является полным callback interface
движка размером 325068. Внутренние варианты клиента имеют размеры 568 и 325056
соответственно. Они отмечены как отдельные внутренние варианты и не являются
источником этих публичных layout движка.

Supplement сохраняет установленные публичные имена полей через явные
соответствия штатных и закрепленных имен. Штатное `CHudMessage::m_pMessages`
соответствует `m_Messages`, массиву из 16 элементов `client_message_t` по
смещению 20. Штатные `playermove_t::player_mins` и `player_maxs` соответствуют
`_player_mins` и `_player_maxs`, с эквивалентным хранением `float[4][3]` по
смещениям 324852 и 324900. Функции tutor-buffer и проверки параметра
`enginefuncs_t` сохраняют публичные имена; запись соответствий содержит точные
типы функций и смещения в таблице.

Три штатные Linux function tables имеют дополнительные конечные поля,
установленные непосредственно по DWARF и проверенные отдельными compiler probes
полных таблиц:

| Запись | Полный размер | Конечное поле | Смещение | Тип указателя на функцию |
|---|---:|---|---:|---|
| `cl_enginefunc_t` | 540 | `pfnFilteredClientCmd` | 536 | `int (*)(char *)` |
| `cl_enginefunc_dst_t` | 492 | `pfnFilteredClientCmd` | 488 | `void (*)(char **)` |
| `enginefuncs_t` | 636 | `pfnPEntityOfEntIndexAllEntities` | 632 | `edict_t *(*)(int)` |

Эти указатели не являются вариадическими и используют стандартное C calling
convention Linux x86. Каждая проба полной таблицы проверяет смещение каждого
поля и полный layout по штатным измерениям. Преднамеренно неверное смещение
конечного поля должно приводить к ошибке проверки компилятора.

## Контракт supplement

`schema_version` равен 1; `target` равен `i686-pc-linux-gnu`; `engine_build` равен
8684. `base_facts_sha256` хеширует каноническую UTF-8 сериализацию
`json.dumps(facts, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`.
Хеш исходных байтов input сохраняется отдельно. Оба идентификатора относятся
к неизмененному Windows extraction.

`records` использует существующую схему фактов, включая вложенные записи и
оригинальные ключи записей. `measurements` индексирует каждый материализованный
ключ, включая вложенные ключи, и связывает его с оригинальной пробой, штатным
DIE при наличии и независимой проверкой компилятора. Новые поля штатных таблиц
имеют идентификаторы, связанные с бинарником. `sources`, `tools` и
`field_correspondences` описывают происхождение и согласованные имена без
передачи реализации исходников.

`self_check.completed` может быть истинным только при совпадении вычисленного
материализованного замыкания с `required_records` и `verified_records`, наличии
реальных успешных записей проверки у каждого измерения и нулевом числе ошибок,
неразрешимых значений, других ошибок и отсутствующих записей. Неизвестное
измерение не может заменяться Windows layout. Полные command manifests и
контроли отказа сохраняются вместе с сырыми доказательствами.

Финальная проверка охватывает все 122 записи, 1877 смещений полей полных записей
и восемь смещений баз. Все 45 бинарников измерений GCC повторно выполнены с
идентичным выводом; все 45 проверок Clang прошли. Зафиксировано 3103 успешных
compiler assertions, включая отдельные проверки полных штатных таблиц.
Числовые сводки сохраняются в `compiler/gcc-replay-manifest.json`,
`compiler/clang_cross_manifest.json` и `supplement-verification.json` внутри
каталога доказательств.

Сохраненный extraction workspace предоставляет числовой verifier, запускаемый
из корня репозитория:

```text
python build/abi-evidence/linux/verify_linux_facts.py
```

Он сравнивает финальный supplement с независимыми числовыми манифестами и
проверяет отказ при неверном полном размере `CHud`, смещении SteamID и глубине
указателя `char **` конечной функции. Оригинальная реализация и replacement
headers не читаются.

## Дескрипторы совместимости Linux

Платформенная ветвь NitroApi для Linux предоставляет глобальные непрозрачные
псевдонимы дескрипторов `HINSTANCE`, `HMODULE`, `HWND`, `HDC` и `HGLRC` для потребителей.
Все пять имеют тип `void *`, размер и выравнивание четыре в x86. Источник:
`common/port.h:61-64` закрепленной ревизии SDK
`e3130f351307968101ae569f609ce2c2d4b8eb3e` с замороженным идентификатором входа
`dep/NclNitroApi/dep/ncl-hl1-source-sdk`. SHA-256 файла:
`c656199776296b9729e4a74c6a6ea077952247d5e0876142abf04ff3a8f090db`.

Файл `public/engine_launcher_api.h:54` той же ревизии устанавливает непрозрачный
параметр instance типа `void *` у `IEngineAPI::Run`; SHA-256 файла:
`aeba8233edd1b0974f499f1f1808fb394fe72f5cc3b086f0a2f645b8d04f1352`.
Правила владения и допустимость null из него не следуют. GCC 15.2 и Clang 22.1.3
независимо проверили четыре псевдонима и точную сигнатуру метода launcher с
14 утверждениями каждым компилятором для `i686-pc-linux-gnu`. Оба компилятора
отклонили отрицательный контроль с целочисленным дескриптором. Числовые факты,
фактические команды и хеши исходников сохранены в
`build/abi-evidence/linux/port-handles-facts.json`. Псевдонимы принадлежат
платформенным объявлениям совместимости NitroApi; новых записей или layout
`goldsrc` в генерируемые модели они не добавляют.

`HMODULE` установлен тем же входом в `common/port.h:47`, в ветви вне Windows.
Дополнительные проверки GCC и Clang подтвердили его тип `void *`, размер и
выравнивание x86 и отклонили контроль с целочисленным псевдонимом.
