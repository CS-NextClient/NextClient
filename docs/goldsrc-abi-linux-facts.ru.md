# Источники фактов об ABI GoldSrc для Linux x86

[English version](goldsrc-abi-linux-facts.md)

Дополнение для Linux [facts_linux.json](../nextclient/goldsrc_abi/tools/facts_linux.json)
содержит независимые измерения штатного 32-битного ABI для сборки движка 8684.
ABI определяет двоичный интерфейс: размещение данных в памяти и правила вызова
функций. Правила сопровождения объявлений описаны в
[справочнике](goldsrc-abi.ru.md). Зафиксированные факты для Windows и
идентификаторы исходных файлов и объявлений хранятся в
[facts.json](../nextclient/goldsrc_abi/tools/facts.json).

## Источники измерений

Для извлечения фактов используются исходники ревизии NextClient
`a64b71ecbbe10d7f0d601c3e210e98ef2ace2550`, ревизии NitroApi
`669639de5e998cf35c32bcaa121e2c57e284930b` и ревизии SDK
`e3130f351307968101ae569f609ce2c2d4b8eb3e`. Их исходные пути, включая
`dep/NclNitroApi/dep/ncl-hl1-source-sdk`, входят в идентификаторы зафиксированных
записей. Для извлечения берутся копии из соответствующих объектов Git.
Рабочий SDK не изменяется, а новые объявления ABI не используются как эталон
размещения данных в памяти.

Два штатных бинарных файла содержат независимые отладочные данные DWARF в
формате ELF32-i386:

| Бинарный файл | SHA256 |
|---|---|
| `hw.so` | `1e775773292407106ac17c98bc19f0444e8f1525d46e592de5cc53afad2b89e1` |
| `cstrike/cl_dlls/client.so` | `40283f3e0c4b6bd21f9281304957ab93c04c60ce5f3d2794cdaf58b3c11ab798` |

Статический анализ подтверждает сборку движка 8684. Функция `build_number` по
виртуальному адресу `0x000f4e80` читает глобальную переменную `date` по адресу
`0x002d53b0`. Хранящийся в ней указатель ведет к строке `Aug  3 2020` по адресу
`0x0026b810`. Дизассемблирование показывает расчет номера сборки: начальный год
1901, множитель 365.25, отбрасывание дробной части, номер дня, поправка на
високосный год и вычитание `0x88b3`. Результат равен 8684. Бинарный файл клиента
взят из той же установленной копии игры Steam и зафиксирован отдельным хешем.
Во время извлечения игра не запускалась.

GNU Binutils 2.42 извлекает данные DWARF. GCC 15.2.0 измеряет полные исходные
объявления с `-m32 -std=c++23`. Clang 22.1.3 независимо проверяет эти измерения
с `--target=i686-pc-linux-gnu -m32 -std=c++23` и имеющимся sysroot Linux,
каталогом заголовков и библиотек целевой платформы. Отдельно проверяется, что
указатели и `wchar_t` занимают четыре байта. Дополнение содержит точные команды
в виде массивов, параметры компиляторов, идентификаторы проверочных программ
и результаты.

Исходные данные, проверочные программы с оригинальным кодом, выгрузки DWARF и
диагностика хранятся в `build/abi-evidence/linux/`. Авторы объявлений работают
с дополнением и этим справочником. Вспомогательные файлы для извлечения
подключают имеющиеся сетевые заголовки Linux и выбирают скалярные псевдонимы
SDK через `GNUC` и `NO_HLSDK_ARCHTYPES`. Исходные объявления структур при этом
не изменяются. Из копии `com_model.h` для извлечения исключено повторное
объявление `cache_user_s`: то же зафиксированное определение предоставляет
`quakedef.h`. Ни одна из проверяемых структур не изменена. Байты всех исходных
файлов сверяются с зафиксированными архивами.

## Какие структуры проверены и как сопоставлены источники

Набор структур, необходимых для генерации с учетом зависимостей, содержит 117
структур верхнего уровня и пять вложенных структур. Для полных объявлений и
объявлений с описанным началом измеряются полный размер в Linux, выравнивание,
смещения базовых классов и полей. Даже при совпадении размещения данных в
Windows и Linux нужна отдельная запись для Linux. Объявление с описанным
началом резервирует память под всю штатную структуру, включая неописанные поля.

| Структура | Размер в Linux | Выравнивание в Linux |
|---|---:|---:|
| `hud_player_info_t` | 28 | 4 |
| `CHud` | 27508 | 4 |
| `CHudMessage` | 16744 | 4 |
| `server_t` | 287756 | 4 |
| `server_static_t` | 132 | 4 |

Данные DWARF штатных файлов соответствуют идентификаторам 121 обязательной
структуры. Структура NitroApi `EngineMsg` проверена по зафиксированному
исходнику обоими компиляторами. DWARF дает полные размеры, включая неописанную
часть структур. Проверочные программы с полными исходными объявлениями и
независимые проверки компилятором определяют выравнивание и подтверждают
смещения. В DWARF2 для этих штатных структур нет явного атрибута выравнивания.

Чтобы выбрать правильный внутренний вариант структуры, используется бинарный
файл, которому она принадлежит. Структуру движка `player_info_t` использует
`client_state_t::players`; ее измеренный размер в `hw.so` равен 592.
`playermove_t` описывает полный интерфейс обмена данными и функциями обратного
вызова с движком и занимает 325068 байт. Внутренние варианты клиента занимают
568 и 325056 байт соответственно. Они записаны как отдельные варианты и не
используются для определения размещения этих публичных структур движка.

Дополнение сохраняет публичные имена полей с помощью явного сопоставления
штатных имен с зафиксированными. Штатное `CHudMessage::m_pMessages`
соответствует `m_Messages`, массиву из 16 элементов `client_message_t` по
смещению 20. Штатные `playermove_t::player_mins` и `player_maxs` соответствуют
`_player_mins` и `_player_maxs`, с эквивалентным представлением `float[4][3]`
по смещениям 324852 и 324900. Функции работы с буфером обучающих сообщений
(tutor-buffer) и проверки параметра в `enginefuncs_t` сохраняют публичные
имена. Запись сопоставления содержит точные типы функций и смещения в таблице.

У трех штатных таблиц функций Linux есть дополнительные поля в конце.
Они определены непосредственно по DWARF и проверены отдельными программами
с полными объявлениями таблиц:

| Структура | Полный размер | Последнее поле | Смещение | Тип указателя на функцию |
|---|---:|---|---:|---|
| `cl_enginefunc_t` | 540 | `pfnFilteredClientCmd` | 536 | `int (*)(char *)` |
| `cl_enginefunc_dst_t` | 492 | `pfnFilteredClientCmd` | 488 | `void (*)(char **)` |
| `enginefuncs_t` | 636 | `pfnPEntityOfEntIndexAllEntities` | 632 | `edict_t *(*)(int)` |

Функции по этим указателям принимают фиксированное число аргументов и используют
стандартное соглашение о вызовах C для Linux x86. Каждая программа с полной
таблицей сверяет смещение каждого поля и размещение всей таблицы со штатными
измерениями. Проверка компилятором должна отклонять намеренно неверное смещение
последнего поля.

## Требования к дополнению

`schema_version` равен 1; `target` равен `i686-pc-linux-gnu`; `engine_build` равен
8684. `base_facts_sha256` содержит хеш канонической сериализации UTF-8,
полученной вызовом
`json.dumps(facts, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`.
Хеш исходных байтов хранится отдельно. Оба хеша идентифицируют неизмененные
результаты извлечения для Windows.

`records` использует существующую схему фактов, включая вложенные записи и
исходные ключи структур. `measurements` содержит запись для каждого ключа
структуры, включенной в генерируемую модель, в том числе вложенной. Запись
связывает ключ с исходной проверочной программой, штатной записью отладочной
информации DWARF (DIE), если она есть, и независимой проверкой компилятором.
Идентификаторы новых полей штатных таблиц привязаны к конкретному бинарному
файлу. `sources`, `tools` и `field_correspondences` описывают происхождение
фактов и сопоставление имен, не включая реализацию из исходников.

`self_check.completed` может иметь значение true только при выполнении всех
условий: вычисленный набор структур с учетом зависимостей совпадает с
`required_records` и `verified_records`; у каждого измерения есть результаты
реальных успешных проверок; число неудачных проверок, значений, которые не
удалось определить, прочих ошибок и отсутствующих записей равно нулю.
Неизвестное измерение нельзя заменять размещением данных для Windows. Полные
списки команд и проверки с заведомо неверными данными хранятся вместе с
исходными материалами.

Итоговая проверка охватывает все 122 структуры, 1877 смещений полей полных
структур и восемь смещений базовых классов. Все 45 измерительных программ GCC
повторно запущены с идентичным выводом; все 45 проверок Clang прошли. В
результатах записано 3103 успешных проверочных утверждения компилятора,
включая отдельные проверки полных штатных таблиц. Числовые сводки хранятся в
`compiler/gcc-replay-manifest.json`, `compiler/clang_cross_manifest.json` и
`supplement-verification.json` в каталоге материалов проверки.

В сохраненном рабочем каталоге извлечения есть скрипт для проверки числовых
фактов. Он запускается из корня репозитория:

```text
python build/abi-evidence/linux/verify_linux_facts.py
```

Скрипт сравнивает итоговое дополнение с независимыми числовыми сводками и
проверяет, что намеренные ошибки обнаруживаются: неверный полный размер `CHud`,
смещение SteamID и число уровней указателя `char **` у последней функции
таблицы. Исходная реализация и новые заголовки ABI при этом не читаются.

## Дескрипторы для совместимости в Linux

Платформенные объявления NitroApi для Linux предоставляют глобальные псевдонимы
непрозрачных дескрипторов `HINSTANCE`, `HMODULE`, `HWND`, `HDC` и `HGLRC`.
Непрозрачный дескриптор скрывает тип объекта, на который он указывает. Все пять
псевдонимов имеют тип `void *`, размер и выравнивание четыре байта на x86.
Источник: `common/port.h:61-64` зафиксированной ревизии SDK
`e3130f351307968101ae569f609ce2c2d4b8eb3e` с идентификатором исходных данных
`dep/NclNitroApi/dep/ncl-hl1-source-sdk`. SHA-256 файла:
`c656199776296b9729e4a74c6a6ea077952247d5e0876142abf04ff3a8f090db`.

Файл `public/engine_launcher_api.h:54` той же ревизии задает непрозрачный
параметр instance типа `void *` у `IEngineAPI::Run`. SHA-256 файла:
`aeba8233edd1b0974f499f1f1808fb394fe72f5cc3b086f0a2f645b8d04f1352`.
Этот файл не определяет правила владения объектом и допустимость null.
GCC 15.2 и Clang 22.1.3 независимо проверили четыре псевдонима и точную
сигнатуру метода запуска с 14 проверочными утверждениями у каждого компилятора
для `i686-pc-linux-gnu`. Оба компилятора отклонили проверочный пример с
целочисленным дескриптором. Числовые факты, точные команды и хеши исходников
хранятся в `build/abi-evidence/linux/port-handles-facts.json`. Псевдонимы
относятся к платформенным объявлениям совместимости NitroApi и не добавляют
структур или сведений о размещении данных `goldsrc` в генерируемые модели.

`HMODULE` определен в тех же исходных данных, в `common/port.h:47`, в ветви для
платформ вне Windows. Дополнительные проверки GCC и Clang подтвердили его тип
`void *`, размер и выравнивание для x86 и отклонили пример с целочисленным
псевдонимом.
