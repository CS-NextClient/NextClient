# Работа с NitroApi

[Английская версия](nitro-api.md) | [Архитектура проекта](architecture.ru.md) | [Жизненный цикл кадра](performance-architecture.ru.md#жизненный-цикл-кадра)

NitroApi дает модулям NextClient доступ к функциям и данным штатной игры. Например, монитор использует NitroApi, чтобы определить начало и конец кадра. Сведения о поддерживаемых версиях движка собраны здесь, поэтому каждому модулю не нужно самостоятельно учитывать их различия.

## Перед изменением

Определите, какому модулю нужна новая возможность и какие данные движка для этого требуются. Проверьте, есть ли нужный доступ в NitroApi. Изменения должны учитывать поддерживаемые версии движка на Windows и Linux.

Прочитайте [правила модуля](../nextclient/nitro_api/AGENTS.md). Подготовка заголовков для совместимости с движком описана в [руководстве по ABI](goldsrc-abi.ru.md).

## Проверка

Соберите NitroApi и модули, которые используют измененный интерфейс, из одной версии исходников и с одинаковыми настройками сборки. Запустите соответствующие тесты из `nitro_api-tests`. При изменении общего интерфейса проверьте, что собранная библиотека загружается и предоставляет этот интерфейс, по [процедуре проверки библиотеки](testing/installation-and-factory.ru.md).

Сборка и тесты без игры проверяют только часть совместимости. Работу со штатным движком разработчик проверяет в установленной игре и записывает результат отдельно.
