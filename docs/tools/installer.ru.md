# Сборка установщика для Windows

[Английская версия](installer.md) | [Установка и обновление игры](../installation.ru.md) | [Проверка](../testing/installer.ru.md)

Скрипт `tools/installer/build_installer.ps1` упаковывает готовую папку Windows Release в самостоятельный установщик. Результат содержит EXE, его контрольную сумму SHA-256 и манифест сборки.

## Требования

- Windows, Git и Windows PowerShell 5.1 или PowerShell 7.
- Полный пакет Windows x86 Release из того же состояния исходников, включая распространяемые модули и все файлы `assets/`. Подготовьте его по [инструкции сборки](../../README.ru.md) с помощью общего скрипта установки. Задайте в `NEXTCLIENT_INSTALL_DIR` абсолютный путь к папке пакета, например `<репозиторий>\install`, и соберите `BUILD_ALL` с отключенными тестами.
- Доступ к интернету для начальной подготовки инструментов или готовый кеш инструментов.

Скрипт подготавливает Python 3.12.10 x86, зависимости, закрепленные в `installer/requirements-build.txt`, и Inno Setup 6.7.3. Загруженные архивы Python и Inno Setup сверяются с закрепленными контрольными суммами. Инструменты кешируются в `build/installer-tools`. Запускайте скрипт в Windows PowerShell или PowerShell 7 с политикой выполнения, которая разрешает локальные скрипты, например `RemoteSigned`.

## Упаковка и проверка

После подготовки пакета Release выполните из корня репозитория:

```powershell
.\tools\installer\build_installer.ps1 -Payload install -Version 2.6.0-preview.1 -SmokeTest
```

Команда выполняет модульные тесты установщика, собирает установщик и проверяет отдельный установщик на синтетических файлах. Она выводит пути артефактов и папку журналов проверки. [Процедура проверки](../testing/installer.ru.md) описывает ожидаемые результаты и проверку интерактивного мастера.

Относительные пути параметров считаются от корня репозитория. После выполнения восстанавливается рабочая папка вызывающего процесса. Для пакета вне репозитория или другой папки результата:

```powershell
.\tools\installer\build_installer.ps1 -Payload "D:\Artifacts\NextClient" -Output "D:\Artifacts\Installer" -SmokeTest
.\tools\installer\build_installer.ps1 -Help
```

## Параметры

| Параметр | Поведение |
|---|---|
| `-Payload` | Папка готового пакета Release; по умолчанию `install`. |
| `-Version` | Версия для имени файла, например `2.6.0-preview.1` или `v1.2.3`. По умолчанию версия проекта CMake с суффиксом `-local.<первые восемь символов ревизии Git>`. |
| `-Output` | Выходная папка; по умолчанию `out/installer/<версия>`. |
| `-ToolsDirectory` | Кеш инструментов и виртуальной среды; по умолчанию `build/installer-tools`. |
| `-Python`, `-Iscc` | Пути к существующим Python 3.12 x86 и компилятору Inno Setup. |
| `-SkipTests` | Пропускает модульные тесты, если уже есть успешный результат для того же снимка затронутых исходников и конфигурации. |
| `-SmokeTest` | После упаковки проверяет собранные средства установки и отдельный синтетический установщик; выводит папку журналов проверки. |
| `-Help` | Выводит справку и параметры. |

Скрипт упаковывает переданную папку. Нативные модули собираются и копируются в нее обычной сборкой клиента. Оригинальные файлы Valve берутся из Steam при установке игры и не входят в пакет выпуска.

## Проверка результата

Выходная папка содержит:

| Файл | Назначение |
|---|---|
| `NextClient-<версия>-setup.exe` | Установщик для распространения среди игроков. |
| `NextClient-<версия>-setup.sha256` | Контрольная сумма SHA-256 файла EXE. |
| `NextClient-<версия>-setup.manifest.json` | Ревизия и состояние рабочего дерева, конфигурация Release, версии Python и PyInstaller, состав пакета, пути артефактов, их размеры и хеши. |

Убедитесь, что манифест указывает нужную ревизию исходников и пакет. Сверьте хеш EXE с файлом контрольной суммы. Пакет отклоняется при отсутствии обязательных файлов, наличии посторонних файлов, неподдерживаемых бинарных файлов Windows или указателей Git LFS. Перед повторной попыткой устраните указанную ошибку входных данных или инструментов.

Средства установки распространяются с лицензиями среды выполнения и сведениями о происхождении кода. Установка нативных модулей и проверка интерфейса NitroApi описаны в [процедуре проверки установки](../testing/installation-and-factory.ru.md).

## Релизный workflow

Публикация выпуска запускает существующий workflow сборки нативных модулей. Зависимая Windows-задача установщика получает его артефакт `NextClient-${{ github.sha }}`, упаковывает установщик и выполняет его проверки. Для упаковки используется этот артефакт без повторной сборки нативных модулей.

Задача публикации ожидает сборку нативных модулей и задачу установщика. Она загружает EXE, контрольную сумму и манифест вместе с существующими архивами и включает их в подтверждение происхождения сборки. Журналы проверки загружаются отдельно от файлов выпуска. Ошибка проверки установщика блокирует публикацию.
