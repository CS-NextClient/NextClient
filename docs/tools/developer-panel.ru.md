# Панель инструментов разработчика

[English version](developer-panel.md)

Панель на Tkinter запускает инструменты репозитория через формы с параметрами и показывает их вывод в общем журнале. Открытие окна не запускает утилиты. Английский язык используется по умолчанию. Для русского языка доступны переключатель **RU / EN** и параметр `--language ru`. Переключение сохраняет значения полей, выбранный инструмент и журнал. Переведены тексты панели, проверки ввода, сообщения состояния, заголовки и фильтры диалогов, справка командной строки. Исходный stdout/stderr утилит сохраняется без перевода. Язык стандартных кнопок системных диалогов определяется операционной системой.

## Запуск

Требуется Python 3.12 или новее с Tkinter. Из корня репозитория выполните одну команду: пусковой файл Windows, пусковой файл POSIX или прямой вызов Python.

```text
tools\dev_tools.cmd
sh tools/dev_tools.sh
python tools/dev_tools/dev_tools.py
```

Оба пусковых файла находятся непосредственно в `tools/` и работают из любого текущего каталога. Если `NEXTCLIENT_PYTHON` содержит путь к исполняемому файлу Python, используется этот интерпретатор. Иначе скрипты проверяют наличие встроенного Python Codex, затем системного Python: `py -3` или `python` в Windows, `python3` или `python` в POSIX-скрипте. Аргументы и код завершения сохраняются. Скрипты не меняют системные настройки. Все Python-утилиты используют тот же интерпретатор, что и панель.

Конфигурацию сервера можно выбрать при запуске:

```text
python tools/dev_tools/dev_tools.py --config build/test-server/config.local.json
```

Относительные пути в полях разрешаются от корня репозитория. Значения сохраняются на время работы окна. Длинные формы доступны через вертикальную полосу прокрутки. Во время выполнения операции переключение языка и элементы управления операциями заблокированы.

## Документация

Кнопки в шапке открывают [всю документацию](../README.ru.md), [указатель проверок](../testing/README.ru.md) и это **руководство панели**. В каждой форме есть кнопка **Руководство инструмента**. На серверной вкладке также доступны [руководство сервера](test-server.ru.md) и [плагин проверки материалов](../testing/materials-test-plugin.ru.md).

Кнопки открывают локальные файлы Markdown в приложении, назначенном операционной системой. Документы открываются на текущем языке панели: английском или русском. Документация доступна во время выполнения утилиты. Если файл отсутствует или системное средство открытия недоступно, панель показывает диалог ошибки. Для открытия требуется назначенное приложение Markdown или системная утилита платформы.

## Инструменты

На каждой вкладке, кроме сервера, есть выбор инструмента и форма с его параметрами. Кнопка **Выполнить** запускает только выбранную форму. Утилиты могут перезаписывать файлы результата с совпадающими именами.

| Вкладка | Подключенные инструменты | Параметры и результат |
|---|---|---|
| Изображения | `flags/convert_flags.py`, `flags/make_country_column_icon.py` | Папка исходных PNG, папка или файл результата. Создаются флаги TGA 16×16 или значок столбца страны. |
| Изображения | `material_masks/make_masks.py` | Папка результата, по умолчанию `assets/cstrike/materials`. Создается полная коллекция изображений 512×512. |
| Материалы matgen | `matgen uv`, `matgen check`, `matgen bake edges` | Готовый исполняемый файл, модель или материал. Команды принимают папку результата, размер, семейство скинов либо каталог игры. |
| Studio | `mdl_flags.py` | Исходный MDL, папка результата, необязательное изменение только первой текстуры. |
| Studio | `make_labels.py` | Выходной WAD и ASCII-метки через пробел. Родительская папка результата должна существовать. |
| Studio | `make_finish_sample.py` | MDL, имя текстуры модели, необязательный путь PNG узора. Создаются пять изображений и соседний MAT. |
| Studio | `make_maps.py` | Папка результата, варианты MDL, папка и имена моделей для нагрузочной проверки, их количество, модель с перекраской и ее файл, основной WAD и WAD подписей. |
| Studio | `make_studio_tests_preset.py` | Файл MAT для образца пресета материалов. |
| Studio | `build_maps.ps1` | Каталог игры `cstrike` и одно имя карты за запуск. Компилирует и устанавливает BSP внешними компиляторами игры. |
| Сравнение изображений | `imgdiff.py` | Эталонное и проверяемое изображения, необязательная область и тепловая карта, допуск RGB, допустимая доля различий и все пороги скоплений. |

Поле каталога игры на вкладке **Studio** и кнопка **Заполнить пути из каталога игры** задают связанные пути моделей, WAD, исходника карты и пресета. Выберите локальную установку перед заполнением путей или укажите каждый путь вручную. Поля, зависящие от установки, изначально пусты. Для компиляции карт нужно явно указать каталог игры. Требования к данным описаны в документации [Studio](studio-content.ru.md), [изображений материалов](material-masks.ru.md) и [сравнения изображений](image-comparison.ru.md).

Исполняемый файл matgen выбирается вручную или находится в `out/bin/` и выходных каталогах настроенных сборок CMake внутри `build/`. Поиск проверяет подкаталоги конфигураций, файлы `CMakeCache.txt` для текущего репозитория, сохраненные пути вывода и `out/bin/` внутри каталога сборки. Последний вариант используется в Linux, тестовых сборках и сборках с профилировщиком. Каталоги зависимостей исключены из поиска. В Windows выбирается `matgen.exe`, на остальных платформах: `matgen`. Явно выбранный исполняемый файл имеет приоритет. Панель не собирает его автоматически.

Пустая папка результата matgen означает сохранение рядом с моделью. Если размер не указан, используются размеры текстур модели. Семейство скинов по умолчанию: `0`. Для `check` пустой каталог игры означает корень репозитория, который используется как рабочий каталог утилит. Правила размеров, проверок и результатов приведены в [документации matgen](matgen.ru.md).

Компиляция карт в Windows вызывает `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File ...` со списком аргументов. Политика выполнения применяется только к этому вспомогательному процессу. Четыре компилятора карт должны уже находиться в папке `tools/` корня игры. Панель не загружает и не собирает их.

## Выделенный сервер

Доступны все публичные [команды сервера](test-server.ru.md):

| Команды | Используемые поля |
|---|---|
| `prepare` | Конфигурация, необязательные репозиторий и модуль API, необязательная переустановка базы Valve. Устанавливает все поддерживаемые плагины. |
| `init` | Конфигурация и необязательная переустановка базы Valve. Устанавливает базу и TestLab. |
| `doctor`, `build`, `compile-only`, `results`, `status`, `stop` | Конфигурация. `compile-only` компилирует TestLab без установки сервера. |
| `start` | Конфигурация и необязательные карта, IPv4-адрес и порт. |
| `smoke` | Конфигурация, набор проверок, необязательные карта, порт и вариант, от 1 до 5 повторений. Запускает и останавливает сервер. |
| `calibrate` | Конфигурация и необязательная карта `cs_office` или `de_dust2`. Запускает и останавливает сервер. |
| `report` | Конфигурация и обязательный идентификатор запуска. |

Глобальный параметр `--config` передается перед каждой подкомандой. `prepare` и `init` создают отсутствующую конфигурацию. `compile-only` также может работать со значениями по умолчанию без сохраненного файла. Остальные серверные операции панели требуют существующую конфигурацию. Пустые поля API используют сохраненные значения или автоматический поиск. Значение `auto` явно запрашивает поиск. Поля API применяются при подготовке. Карта, порт и параметры smoke передаются только тем командам, которые поддерживают их в CLI.

Подготовка может загружать данные Steam и зависимости, но не запускает сервер. Каждое действие требует нажатия кнопки. Остановка всегда использует проверки принадлежности процесса из серверного CLI. Панель сама не завершает сервер. Закрытие блокируется на время операции. Если окно помнит работающий сервер либо неподтвержденный запуск или остановку, при закрытии требуется явно выбрать продолжение его работы. Для остановки отмените закрытие, выберите конфигурацию и нажмите **Остановить**. Кнопка **Статус** обновляет сведения о выбранном сервере. Автоматического опроса при открытии и постоянного наблюдения за процессами нет.

## Зависимости и выполнение

Панель использует Tkinter и стандартную библиотеку Python. Для флагов, подписей и образца покрытия требуется Pillow. Для коллекции материалов и сравнения изображений требуются Pillow и NumPy. Если пакет отсутствует, панель показывает команду установки для используемого интерпретатора Python. Установка выполняется отдельно, например:

```text
python -m pip install Pillow numpy
```

Одна операция выполняется за раз в фоновом потоке. Журнал показывает список аргументов, общий stdout/stderr и результат завершения. Вспомогательные консольные окна Windows скрыты. Перед закрытием дождитесь завершения операции. Принудительная отмена процесса не предусмотрена. Серверные ограничения времени задаются в конфигурации сервера. Журнал хранит последние 200 000 символов. Кнопка **Сохранить журнал...** экспортирует отображаемую часть в UTF-8. Код сравнения `1` отображается как неуспешное сравнение; его показатели остаются в журнале.

Внутренние модули `tools/test_server/` (`all_plugins`, `common`, `install`, `profiles`, `report`, `results`, `runtime`, `steam_process`) вызываются через публичный CLI сервера и не имеют отдельных кнопок. Модульные тесты служат для проверки кода и не относятся к операторским инструментам. Все операторские скрипты перечисленных групп подключены.

## Проверка

```text
python -X utf8 -m unittest discover -s tools/dev_tools/tests -v
python -X utf8 tools/dev_tools/dev_tools.py --language en --self-check
python -X utf8 tools/dev_tools/dev_tools.py --language ru --self-check
```

Тесты проверяют команды, процессы, работу окна, параметры утилит, полноту перевода, переключение языка, коды завершения пусковых файлов и небольшие результаты генераторов во временных каталогах. Для оконных тестов требуются рабочий стол и доступ Tcl/Tk к своим файлам. Самопроверка создает и закрывает скрытое окно без запуска утилит. Тесты не запускают игру или реальный сервер, не обращаются к Steam, не устанавливают зависимости, не компилируют карты, не запускают генерацию matgen и не пересоздают полную коллекцию изображений.
