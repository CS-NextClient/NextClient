# Как читать графики производительности

[Английская версия](performance-graphs.md)

Встроенный монитор доступен в Release-сборках. `cl_perf 2` включает сгруппированные графики, `cl_perf 1` показывает числовые таблицы, `cl_perf 3` показывает отдельные графики. Настройки и диагностический захват описаны в [руководстве по мониторингу](performance-monitor.ru.md). Проверки во время игры перечислены в [сценариях проверки](testing/performance-monitor.ru.md).

Изображения получены штатным рендерером панели вне игры, с синтетическими измерениями при 1600x1200 и `cl_perf_scale 1`.

## Группы измерений

В таблице CPU строка Host Frame вложена в Swap Interval, а Studio, Radar и Swap вложены в Host Frame. Host Frame измеряет обработку принятого кадра Host и вызовы его подписчиков, включая подготовку рендеринга, отправку команд и ожидания. В него входит и работа за пределами обновления игровой симуляции. Swap Interval измеряет время между завершенными обменами буферов главного окна, включая ограничение частоты и ожидания. Отступы показывают работу, связанную с кадром. Границы Host и представления кадра не всегда совпадают, особенно при нескольких обменах буферов в одном вызове Host.

График CPU накладывает приглушенные синие столбцы Swap Interval и теплые оранжевые столбцы Host Frame, отсчитывая оба показателя от нуля. Составной столбец содержит Studio, Radar и Swap снизу вверх, в порядке обычного вызова. Все части относятся к той же записи принятого кадра Host, что значение Host Frame на этой позиции. Несколько обменов буферов внутри Host дают одну суммарную длительность Swap.

График GPU накладывает полупрозрачный столбец Render и составной столбец измеренных частей. Studio и Radar расположены снизу вверх и относятся к той же записи выходного кадра, что значение Render. Studio измеряет вызовы шейдерной отрисовки, для которых установлены замеры GPU. Время штатного рендеринга моделей измеряется на CPU. Radar суммирует внешние инструментированные интервалы радара: вложенные запросы карты, слоя и батчей учитываются один раз. Подробные вложенные замеры остаются в диагностике.

Родительский показатель уже включает свои части. Наложенные столбцы и строки таблицы нельзя складывать для получения полного времени кадра. CPU и GPU также выполняют работу параллельно. Оба графика используют общую шкалу длительности: одинаковая высота означает одинаковое прошедшее время.

## Покадровые столбцы и статистика

Заголовок `History | last N frames` обозначает общее окно последних N кадров в хронологическом порядке для таблиц и графиков CPU/GPU в режимах 1/2/3. В числовом режиме 1 значение N определяется шириной поля его панели; режимы 2/3 используют ширину своих графиков. Каждая позиция содержит одно значение кадра для каждой доступной серии. CPU и GPU используют общий порядок позиций. Каждый вывод кадра занимает отдельную позицию. Если один Host создает несколько выходных кадров, его замер CPU и части показываются один раз у последнего выходного кадра.

Host без выходного кадра получает собственную позицию. Новые позиции появляются у правого края и сдвигают предыдущие влево; незаполненная история остается слева внутри графика.

Таблицы CPU/GPU и шкалы графиков используют те же выбранные N позиций кадров, что показанные значения. Во время заполнения истории учитываются доступные измерения на этих позициях. Сохраненная история ограничена числом записей, поэтому при низком FPS N позиций могут охватывать больше десяти секунд. Увеличение N может включить более ранние сохраненные позиции.

N равно физической ширине графика. Каждый столбец кадра имеет ширину один физический пиксель, без зазоров между соседними заполненными позициями. Новая позиция примыкает к правому краю графика. Фон и горизонтальная сетка охватывают всю полосу кадров; вертикальная ось и подписи делений расположены у левого края. Изменение масштаба или разрешения может изменить N, а расширение графика может показать более ранние позиции, еще сохраненные в истории. Незаполненные позиции и отсутствующие значения остаются пустыми внутри графика. Например, график шириной 423 физических пикселя показывает последние 423 позиции кадров. Ширину панели определяет разметка.

Если часть ожидается, недоступна, пропущена, неполна или интервалы перекрываются, соответствующий составной столбец не рисуется. Отсутствующее измерение не превращается в измеренный ноль. Неактивная часть дает ноль. Участок короче одного вертикального пикселя может не иметь видимого цветного сегмента.

Общие значения CPU/GPU показаны полупрозрачными заполненными столбцами. Верхняя граница каждого столбца горизонтальна и соответствует длительности его кадра. Цветные части располагаются внутри этого столбца и относятся к тому же Host или выходному кадру, что общее значение.

Графики CPU/GPU и их числовые сводки обновляются каждые 250 мс. Вертикальная ось показывает миллисекунды: ноль, половину диапазона и верхнюю границу, если для подписей хватает места. Минимальная верхняя граница равна 1 мс. Оба сгруппированных графика используют общую верхнюю границу, выбранную по показанным длительностям Swap Interval, Host Frame и Render. Пока большое значение Swap Interval остается в окне графика, остальные значения занимают меньшую долю высоты. Режим `cl_perf 3` использует отдельную шкалу каждой серии, чтобы рассматривать малые длительности.

## Статистика

Таблицы длительности CPU/GPU обобщают корректные измерения внутри текущего окна из N кадров и используют столбцы `avg`, `p99`, `max` в этом порядке. `avg` обозначает среднее арифметическое корректных измерений. `p99` обозначает 99-й перцентиль по ближайшему рангу: 99% корректных измерений не превышают это значение. Он появляется после 100 корректных измерений соответствующей серии внутри текущего окна; `-` означает недостаточное число измерений. `max` обозначает наибольшее корректное измерение внутри окна. Отсутствующие, ожидаемые и неактивные значения в статистику не входят.

Неактивность показывается явно, если корректных измерений нет. Каждая строка описывает собственные измерения, поэтому статистику разных строк нельзя складывать. Таблицы задержки сети и размера пакетов используют `avg`, `median`, `max` для текущих окон из N позиций пакетов.

`perf_dump` также выводит `p95` для Swap Interval, 95-й перцентиль по ближайшему рангу, и `p99`. Эта статистика истории и FPS дампа используют отдельное десятисекундное диагностическое окно. Флаг `percentiles=1` подтверждает доступность перцентилей после 100 корректных измерений Swap Interval в этой диагностической истории.

FPS в заголовке рассчитывается по положительным интервалам обмена буферов за последние 0,5 секунды: число интервалов делится на их суммарную длительность. Таблица Swap Interval использует текущее окно из N кадров. Для сравнения: 60 FPS соответствуют 16,67 мс, 100 FPS соответствуют 10 мс, 144 FPS соответствуют 6,94 мс.

## Задержка результатов GPU и ожидания

Результаты временных запросов GPU приходят асинхронно, иногда через несколько кадров. Ожидаемые и отсутствующие результаты оставляют пустым значение GPU на исходной позиции кадра. Поздний результат заполняет ту же позицию. CPU и GPU сохраняют общие хронологические позиции, даже если на позиции доступно значение только одного из них. GPU age показывает число выводов кадра, прошедших после кадра, к которому относится последний опубликованный результат GPU. Нулевой возраст сам по себе не подтверждает доступность измерения GPU.

Render измеряет интервал команд GPU от начала экранного рендеринга до завершения панели монитора, перед представлением кадра. Интервалы временных запросов GPU могут включать простой GPU между командами. Длительности CPU измеряют прошедшее время, включая ожидания. Простой GPU может включать паузы, пока CPU готовит следующие команды.

Проход может занимать часть такой паузы, поэтому отключение размытия радара способно уменьшить Radar без равного уменьшения Render. Само по себе неизменное время Render не подтверждает эту причину: следует сравнить строки GPU Backdrop capture и Backdrop blur в perf_dump и изучить временную шкалу CPU/GPU в Tracy.

По Swap нельзя надежно отличить ожидание завершения GPU от VSync или поведения драйвера. Следует сопоставлять Swap Interval, Host Frame, Swap, Render и настройки представления кадра. `cl_perf_gpu 0` отключает запросы GPU во встроенном мониторе.

## Пакетные графики сети

`Network | last N packets` использует горизонтальную ось в порядке пакетов. N равно физической ширине графика: каждая позиция пакета занимает один физический пиксель, без зазоров. Поэтому изменение масштаба панели или разрешения может изменить N. Серии размеров In/Out используют последние N позиций пакетов каждого направления независимо. Задержка и полосы loss/choke используют отдельное общее окно последних N входящих порядковых номеров. Новая позиция находится справа, незаполненная история остается слева внутри графика.

Каждое окно сдвигается при поступлении следующего пакета или порядкового номера; при отсутствии данных позиции сохраняются. Одинаковые позиции по горизонтали в этих окнах могут относиться к разным моментам времени. Расширение графика может вернуть доступную историю, собранную до расширения. Ось, фон и сетка соответствуют полной полосе пакетов.

Задержка фиксируется после завершения разбора обычного серверного сообщения. Для собранного сообщения из надежных фрагментов отдельный замер задержки не создается. Задержка измеряется в миллисекундах. `Packet size (B)` показывает учтенный движком размер пакетов In и Out в байтах на общей шкале. Сводные строки трафика показывают KiB/s и пакеты в секунду по выборкам с интервалом 100 мс. Таблицы `avg`, `median`, `max` описывают корректные значения текущих окон из N позиций пакетов. При изменении N статистика соответствует новому окну. Недоступные значения в статистику не входят.

Каждый заполненный столбец содержит один замер. Графики задержки сети и размера пакетов рисуют полупрозрачные столбцы. Их верхние границы интерполируются между соседними позициями с данными. Таблицы показывают `avg` для текущего окна пакетов.

Красные маркеры loss и оранжевые маркеры choke под графиком задержки отмечают входящие порядковые номера с подтвержденным состоянием loss или choke на той же пиксельной сетке, что столбцы. Позиции с loss или choke не содержат замера задержки. Сводные значения loss/choke показывают проценты, рассчитанные по периодическим выборкам. Если между наблюдениями поступило больше записей, чем хранит движок, перезаписанные позиции остаются пробелами: история потока хранит по 32 записи каждого направления, история входящих кадров хранит 64 записи. Неизвестная запись не создает нулевой замер или маркер loss/choke.

Новые сетевые данные обновляют сетевую секцию при следующем представлении кадра. Батчинг может обновиться при том же представлении кадра. Графики CPU/GPU и таблицы используют общее окно из N кадров и обновляются каждые 250 мс. Нижняя строка самостоятельной сетевой панели показывает число сохраненных позиций In/Out.

## Подробная диагностика

Строка Monitor показывает средние затраты монитора на CPU за то же окно из N кадров, включая панель и опрос GPU. `perf_dump` захватывает следующий полный принятый кадр Host и печатает его при последующем представлении кадра главного окна. Столбец CPU incl включает вложенные этапы; self исключает измеренные дочерние интервалы. Строки GPU относятся к последнему кадру с готовыми асинхронными результатами GPU и могут предшествовать захваченному кадру CPU. Таблица батчинга отдельно объединяет до восьми принятых кадров Host.

Длительность Worker описывает фоновую обработку радара, ее нельзя добавлять к времени основного кадра. Tracy показывает временную шкалу инструментированных участков.
