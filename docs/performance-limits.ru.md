# Диагностика карты

[Английская версия](performance-limits.md) | [Работа панели](performance-monitor.ru.md) | [Справочник графиков](performance-graphs.ru.md)

## С чего начать

На загруженной карте выполните `cl_perf_map 1` в консоли. Панель покажет счетчики геометрии, позицию и координаты точки взгляда. `cl_perf_map 0` выключает диагностику; по умолчанию она выключена. Панель работает независимо от производительности, сети и батчинга.

Для имени, свойств и обводки объекта запустите локальную игру через `map` и задайте `cl_perf_map 2`. Нужны активный сервер в процессе игры и клиентское соединение loopback, без просмотра демо; число слотов `maxplayers` на доступность не влияет. На внешнем сервере или при просмотре демо действует режим 1. Запрошенное значение квара сохраняется, поэтому режим 2 возвращается на следующей локальной карте.

## Показатели панели

| Строка | Значение |
|---|---|
| wpoly | Штатный счетчик брашевых полигонов из `r_speeds 1` для последнего основного вида, включая мир и брашевые сущности. |
| epoly | Штатный счетчик полигонов моделей плюс треугольники, фактически отправленные шейдерным рендерером NextClient в этом виде. Повторные проходы учитываются повторно. |
| Brush entities: map | Число записей BSP с брашевой моделью `*N`, без worldspawn. Включает брашевые триггеры и другие брашевые сущности карты. Это данные локальной карты, в том числе объекты, которые сервер может удалить или заменить во время работы. |
| Brush entities: PVS | Число брашевых моделей в списке видимых клиентских сущностей для отрисованного вида, без мира. PVS обозначает потенциально видимую область. Здесь используется клиентский список рендеринга, поэтому на число также влияют передача данных сервером и добавление клиентских сущностей. |
| Position | Предсказанная позиция игрока XYZ в единицах карты. Позиция глаз камеры может отличаться. |
| Angles | Углы камеры pitch, yaw и roll в градусах. |
| Look | XYZ ближайшего пересечения луча взгляда с миром или видимым объектом. |
| Object origin (режим 2) | Текущая позиция сущности XYZ, отдельно от точки попадания Look. Для worldspawn используется начало координат мира: 0 0 0. Если объекта нет, выводится прочерк. |
| Object (режим 2) | Classname и targetname брашевой сущности, если ее однозначно определяет запись модели в BSP. Иначе показывается имя модели. Для поверхностей мира выводится worldspawn. Попадания в границы Studio-моделей и спрайтов помечаются `[bounds]`. |

В режиме 2 выбранный объект выделяется голубыми линиями в сцене. Для геометрии мира выделяется только выбранный полигон, для брашевой сущности ее ребра. У Studio-моделей и спрайтов выделяются те же границы модели, по которым определяется попадание. Обводка использует область отрисовки, проекцию и глубину сцены. Ближняя геометрия перекрывает скрытые ребра. Если кадр также содержит меньшее окно наблюдения, основной вид выбирается по наибольшей площади. Если пересечения нет, обводка скрывается, а строки показывают `Look: -` и `Object: -`.

## Свойства объекта

Режим 2 показывает индекс объекта, модель, текстуру поверхности при ее наличии, доступные текущие поля сущности и пары ключ/значение из BSP с префиксом `bsp.`. Свойства BSP содержат исходные значения карты, а не серверные переменные сущности. Текущие поля включают позицию, углы, режим и интенсивность рендеринга, эффекты, skin, body, sequence и solid. Если одной брашевой модели соответствуют несколько записей, classname и свойства BSP не подставляются.

Панель показывает до 16 строк свойств с учетом свободного места и указывает команду `perf_dump` для полного списка и значений без обрезки. При загруженной карте над счетчиками в режимах 1/2 показывается подсказка `E: dump to console`. Нажатие E во время игры сразу печатает текущий снимок диагностики карты в консоль. Каждое нажатие выводит снимок один раз. Обычное действие клавиши E сохраняется. В режиме 1 выводятся координаты точки взгляда без поля Object. В режиме 2 выводятся имя, отдельная строка Object origin с позицией объекта и все доступные свойства объекта. При вводе в консоли, чате или меню снимок не запрашивается. Команда `perf_dump` также включает эти данные в полный замер производительности. Длинные имена и значения обрезаются по ширине панели.

Брашевые объекты выбираются по пересечению с полигонами BSP, включая видимые несолидные браши. Геометрия мира перекрывает более дальние объекты. Studio-модели и спрайты выбираются по границам модели. Такое попадание может оказаться в пустом пространстве внутри границ.

## Доступность данных и срок жизни

Если список сущностей BSP недоступен, строка Brush entities показывает только число брашевых моделей в PVS. До появления отрисованного вида зависимые от него строки содержат `-`. Кадр без отрисованного вида, в том числе при `r_norefresh`, очищает пересечение и обводку. Текст диагностики обновляется по последнему виду независимо от сводок CPU/GPU с интервалом 250 мс.

Замена модели карты или изменение ее поколения, отключение и `perf_reset` сбрасывают кешированные метаданные, геометрию и выбранный объект. После сброса кеша метаданные и дерево границ поверхностей строятся заново, когда текущая карта становится доступна. Диагностика сбрасывает счетчики полигонов для каждого измеряемого вида. Проверки во время работы описаны в [проверке монитора производительности](testing/performance-monitor.ru.md).
