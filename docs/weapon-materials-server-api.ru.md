# Серверное API материалов

[Английская версия](weapon-materials-server-api.md) | [Серверное руководство](weapon-materials-server-guide.ru.md) | [Формат материалов](weapon-materials.ru.md)

Серверный модуль `NextClientServerApi` предоставляет нативы Pawn для привязки материалов к сущностям. Привязка указывает сущность, путь к пресету и имя материала внутри пресета. Пресеты и изображения передаются через механизм докачки приватных ресурсов. Привязки и значения параметров для отдельных сущностей передаются через синхронизацию сущностей. Клиент загружает пресет, когда впервые получает привязку к материалу из этого файла. Для шейдерных материалов требуются `r_studio_shader 1` и `r_studio_materials 1`.

## Нативы

```pawn
native ncl_mat_bind(entity, const preset[], const material[]);
native ncl_mat_unbind(entity, const preset[], const material[]);
native ncl_mat_clear(entity);
native ncl_mat_through_walls(entity, bool:enabled = true);
native ncl_mat_param(entity, const texture[], const name[], Float:value);
native ncl_mat_param_all(entity, const name[], Float:value);
```

Нативы возвращают `1` при успехе или `0` при ошибке. Неверные аргументы отмечаются в журнале серверного модуля. `ncl_mat_unbind` также возвращает `0`, если указанной привязки нет.

| Натив | Контракт |
|---|---|
| `ncl_mat_bind` | Привязать указанный материал пресета. Новая привязка заменяет отрисовываемый материал той же текстуры. Повторная привязка уже существующей пары пресета и материала сохраняет ее состояние. Заданные значения параметров экземпляра продолжают действовать. |
| `ncl_mat_unbind` | Удалить привязку указанного материала пресета. |
| `ncl_mat_clear` | Удалить материалы сущности и прекратить синхронизацию ее материалов. |
| `ncl_mat_param` | Задать скалярный параметр экземпляра для материала, выбранного по имени текстуры модели. |
| `ncl_mat_param_all` | Задать скалярный параметр экземпляра для всех привязанных материалов, которые его объявляют. |
| `ncl_mat_through_walls` | Явно разрешает передачу привязанной сущности вне PVS готовым клиентам NextClient 2.6+. Отключение возвращает синхронизацию материалов по PAS. См. [эффекты](material-effects.ru.md#управление-с-сервера). |

Привязку может иметь любая сущность с edict. Для носимого оружия Counter-Strike серверный модуль применяет привязку к сущности игрока. По этой привязке клиент рисует оружие от первого лица и носимую модель `p_`. После выбрасывания оружия привязка применяется к сущности weaponbox. Серверный модуль обновляет это соответствие при смене владельца. Клиент применяет полученные привязки к индексу отрисовываемой сущности.

В каждой привязке указано имя текстуры модели. Материал получают все меши с этой текстурой. По умолчанию сервер выбирает получателей по области потенциальной слышимости (PAS) сущности. Он передает данные при позднем подключении и возврате в PAS, а также отслеживает серийные номера сущностей. Клиент заменяет привязки и параметры затронутого синхронизируемого владельца. При уничтожении или переносе владельца клиент удаляет только его привязки по сохраненному индексу отрисовываемой сущности. Другие владельцы и консольные привязки сохраняются. Если несколько синхронизируемых владельцев задают материал одной текстуры, используется материал владельца с наибольшим ID синхронизации.

Параметры экземпляра передаются как конечные 32-битные числа float в единицах параметра. Сервер хранит значения отдельно от привязок и отклоняет NaN и бесконечности до регистрации ключей или изменения состояния. Клиент применяет значения к подходящим скалярным параметрам `instance` и ограничивает их объявленными границами. Дробные значения `choice` отклоняются до ограничения границами; целые индексы за границами ограничиваются диапазоном. Некорректный снимок сохраняет предыдущее состояние владельца. При обновлении параметров клиент восстанавливает копии материалов только этого владельца из пресетов, применяет сетевую политику эффектов, затем накладывает полный текущий набор параметров. Удаление параметра возвращает значение из пресета. После удаления параметров активации подкраска скрытых участков и обводка снова отключаются сетевой политикой. Обновление параметров не требует повторного поиска привязок и не пересоздает материалы других владельцев.

| Параметр `weapon_finish` | Диапазон |
|---|---|
| `uWear` | `0..1` |
| `uLayerMix` | `0..1` |

Клиент и сервер используют согласованный формат разрабатываемой версии. Привязки передаются парами ID строк, параметры передаются парами ID ключа и float. Реестр строк содержит только ключи параметров. Сообщения usermsg надежны, упорядочены и содержат не более 192 байт полезной нагрузки. Сервер готовит всю последовательность перед отправкой, разбивает коллекции на сообщения и передает очистку один раз перед заполнением. Создание, позднее подключение и возврат в область рассылки восстанавливают полный набор из сохраненного состояния. Несколько сообщений не образуют атомарную транзакцию.

## Формат пресета

```json
{
    "version": 1,
    "materials": [
        {
            "name": "golden_slide",
            "texture": "glock_slide.bmp",
            "material": {
                "program": "weapon_finish",
                "params": {
                    "uWearMap": { "texture": "materials/masks/wear/blotches.png" },
                    "uWearMapTransform": [8.0, 8.0, 0.0, 0.0],
                    "uUnderlay": { "texture": "materials/surfaces/brass.png" },
                    "uUnderlayTint": [1.0, 0.55, 0.1, 1.0],
                    "uWear": 0.5
                }
            }
        }
    ]
}
```

Поле `name` уникально внутри файла и сравнивается без учета регистра. Поле `texture` задает имя текстуры модели. Объект `material` использует ту же структуру программы и параметров, что и документ модели. При создании привязки используются значения параметров из пресета. Затем к ним применяются значения, заданные для конкретной сущности.

Синхронизация материалов сохраняет полный упорядоченный набор пар пресет/материал. Сервер вычисляет дельты из этого набора. При позднем подключении и возврате в область рассылки клиент получает те же привязки, что и остальные получатели, включая несколько материалов одного пресета. Клиент сохраняет допустимые материалы и тогда, когда для их текстур не хватает места в лимите из 16 текстур отрисовываемой сущности. Сначала места занимают разные консольные текстуры, затем владельцы в порядке убывания ID синхронизации и привязки в порядке запросов каждого владельца. Общая текстура занимает одно место. Первый допустимый запрос резервирует позицию текстуры, а последнее допустимое назначение задает материал этого владельца. При удалении или переносе привязки сохраненный материал может получить освободившееся место без нового обновления своего владельца. Параметры скрытого владельца сохраняют актуальные значения и становятся видны после удаления владельца с более высоким приоритетом.

## Проверка и ограничения клиента

| Ресурс | Лимит |
|---|---|
| Версия пресета | `1` |
| Материалы одного пресета | 128 |
| Различные файлы изображений, указанные в пресете | 64, включая поставляемые изображения |
| Путь изображения | 96 байт |
| Путь файла пресета | 128 байт, относительный путь с расширением `.mat` |
| Размер файла пресета | 1 МиБ |
| Пресеты в кеше | 32, включая записи неудачных загрузок, до очистки кеша |
| Разные текстуры с материалами у одной отрисовываемой сущности | 16 |

Неверная структура, повтор имен, недопустимые пути изображений и превышение лимитов файла приводят к отклонению всего пресета. Пути изображений должны соответствовать [правилам формата материалов](weapon-materials.ru.md#ограничения-файлов-и-изображений). Если программа неизвестна или материал не проходит проверку по манифесту, удаляется этот материал, а допустимые записи сохраняются. При загрузке изображений проверяются данные PNG/TGA и площадь, не превышающая 1 048 576 пикселей.

Модели игроков используют базовую текстуру, которую выбирает движковая функция `StudioSetupSkin`, включая перекраску цветов команды. Материал указывается по исходному имени текстуры, например `DM_Base.bmp`; привязка остается отдельной для каждой сущности. Набор слоев `weapon_finish` предназначен для покрытия оружия и может применяться к другим Studio-моделям.

Клиентская синхронизация реализована в [`MaterialSyncSystem.cpp`](../nextclient/engine_mini/src/client/ncl_entity/MaterialSyncSystem.cpp), хранение и проверка привязок в [`ServerMaterials.cpp`](../nextclient/engine_mini/src/graphics/render/material/ServerMaterials.cpp).
