# Ручные проверки

[English version](manual-testing.md)

Тестовый сервер подготавливает воспроизводимые игровые сцены. Их поведение проверяется в NextClient, который разработчик запускает самостоятельно. В [перечне сценариев](manual-testing-scenarios.ru.md) описаны девять сценариев и 22 варианта ролей и исходов. Каждый вариант выполняется пять раз.

Установка и параметры команд приведены в [справочнике тестового сервера](../../tools/test_server/README.ru.md). Поддерживаемая конфигурация и ограничения описаны в [документе о совместимости](../../tools/test_server/compatibility.ru.md).

Серверные операции, видимость для клиента и визуальная оценка учитываются отдельно. Успешное выполнение операции на сервере не подтверждает получение данных и отрисовку на клиенте. Проверки без подтвержденного результата сохраняют статус `not_run`.

<a id="run-scenario"></a>
## Выполнение сценария

1. На машине сервера откройте терминал в корне репозитория. Установите и проверьте стенд, затем запустите сервер:

   ```text
   python tools/test_server/test_server.py init
   python tools/test_server/test_server.py doctor
   python tools/test_server/test_server.py start --map cs_office
   ```

   В Linux используется `python3`. Для отдельного файла конфигурации во всех командах инструмента добавляется `--config <path>` перед подкомандой. До запуска сервера в Linux необходимо выполнить [настройку окружения](../../tools/test_server/README.ru.md#linux).

2. Запустите NextClient самостоятельно. В консоли клиента подключитесь к серверу:

   ```text
   connect 127.0.0.1:27020
   ```

   Для удаленного сервера укажите его доступный IP-адрес и настроенный порт. Выполните обычный выбор команды и класса.

3. Выберите вариант из [перечня сценариев](manual-testing-scenarios.ru.md), затем задайте роль и исход до запуска. Например, проверка сопровождения заложника для CT запускается так:

   ```text
   nct_trace on
   nct_run radar_hostage_follow ct
   ```

   Роль, сценарий и исход также можно выбрать через `nct_menu`. После действия меню закрывается. Меню и консоль используют один обработчик команд.

4. Дождитесь `ready` и осмотрите подготовленную сцену. Запустите один шаг:

   ```text
   nct_step
   ```

5. Дождитесь `ready` или `finished`. Проверьте результат этого шага и при необходимости получите [диагностику](#diagnostics). Повторяйте пункты 4 и 5 до `finished`. Не вводите команды всех шагов одновременно.

6. [Запишите оценку](#record-result) и сохраните отчет до повтора или смены карты. Следующий повтор запускается командой `nct_repeat`. После завершения сброса каждый прогон получает новый `run_id`.

Если запуск сценария меняет карту, подключитесь заново, выберите команду и класс, затем выполните `nct_resume`. Сохраненный запрос на продолжение можно использовать один раз в течение 120 секунд после запроса смены карты. Выбранный исход сохраняется. Другие случаи сброса и переподключения описаны в разделе [восстановления](#recovery).

При необходимости назначьте клавиши в консоли клиента:

```text
bind F6 nct_menu
bind F7 nct_step
bind F8 nct_repeat
```

<a id="diagnostics"></a>
## Просмотр диагностического снимка

Команда клиента `nct_status` выводит краткую строку состояния. Подробные данные игроков, объектов, видимости и сопровождения записываются в серверный журнал и включаются в HTML-отчет.

1. После перехода сцены в `ready` или `finished` выполните `nct_status` в консоли клиента. Сохраните `run` и `stage`. Если после сброса или отмены поле `run` пустое, используйте `last_run`.
2. На машине сервера выполните из корня репозитория:

   ```text
   python tools/test_server/test_server.py report --run <run_id>
   ```

3. Откройте `html_path` из ответа команды. Путь по умолчанию: `out/manual-tests/<run_id>/report.html`.
4. В таблице «Проверки по шагам» прочитайте ожидаемые и фактические результаты. В разделе «Диагностика и файлы» раскройте «Состояние сцены»: поля `actors` и `objectives` содержат последний сохраненный снимок.
5. Для конкретной стадии раскройте «События (N)» и найдите последнее событие с `event="state"`, то есть с наибольшим `seq` этой стадии. Используйте поля `data.visibility` или `data.hostage_follow`.

| Данные | Поля для проверки |
|---|---|
| Игроки в `actors` | Найдите `role`: `operator`, `nct_t1`, `nct_ct1` или `nct_t2`. Проверьте `userid`, `alive`, `team`, `origin`, `health`, `observer_mode` и `observer_target_userid` |
| Объекты в `objectives` | `entity_index`, `classname`, `hostage_id`, `native_hostage_id`, `owner_userid`, `bomb_state` и `origin` |
| Видимость в `data.visibility` | `pvs`, `los`, `los_hit` и `original_pack` |
| Сопровождение в `data.hostage_follow` | Фаза, маршрут, точка маршрута, подтвержденные переходы, время вне PVS, число сообщений и пройденное расстояние |

LOS обозначает прямую видимость объекта. PVS, набор потенциально видимых областей карты, используется движком для проверки видимости со стороны клиента. `original_pack` показывает, включил ли исходный колбэк `AddToFullPack` сущность в снимок состояния для клиента. До получения данных от колбэка для реального клиента PVS имеет значение `unknown`.

Отчет можно получать между шагами. В промежуточном отчете сценарий еще не завершен, а ручная оценка не записана. После следующего шага соберите отчет заново и обновите страницу. Команда клиента `nct_report` записывает снимок в журнал; HTML- и JSON-файлы создает команда `report --run`.

Сохраненный отчет описывает зафиксированную сцену. После отмены он может содержать состояние до отмены. Сохраните идентификатор до смены карты, повтора или отключения; для следующего прогона используйте новый снимок.

### Выбор цели наблюдения

До повтора или сброса получите снимок текущей сцены. В `actors` найдите цель с `alive=true` и скопируйте ее `userid`. При необходимости переведите оператора в режим наблюдения, затем выберите цель в консоли клиента:

```text
nct_team observer
nct_observe <userid>
```

Дождитесь `observer target confirmed`. Номер слота не является `userid`. После `finished` сцена сохраняется до повтора или сброса, поэтому каждую живую цель можно осмотреть отдельно.

<a id="record-result"></a>
## Запись и передача результата

1. В консоли клиента запишите визуальную оценку с примечанием:

   ```text
   nct_result pass "client=<version>; radar=<settings>; observed=<result>"
   nct_report
   ```

   Используйте `fail` при обнаруженной ошибке или `skip`, если визуальная проверка пропущена. В примечании укажите версию клиента, форму, вращение, масштаб, режим полной карты, подписи и наблюдавшийся результат. Для надежной передачи текста через игровую консоль рекомендуется ASCII.

2. На машине сервера соберите отчет:

   ```text
   python tools/test_server/test_server.py report --run <run_id>
   ```

3. Проверьте независимые статусы и полноту журнала. При `complete=false` прочитайте `issues`. Значение `complete=true` или успешное выполнение команды не подтверждает результат визуальной проверки. Визуальная оценка записывается только вручную, командой `nct_result`.
4. Передайте каталог `out/manual-tests/<run_id>/` с `report.json`, `report.html` и очищенными журналами. При другом `paths.reports` используйте соответствующий каталог прогона.

Запись диагностических событий включается и отключается командой `nct_trace on|off`. Лимит составляет 10 000 событий сообщений и видимости на прогон. Если запись обрезана, это отмечается в отчете. Для широковещательных сообщений сохраняется список получателей на момент отправки.

Не передавайте весь каталог отчетов. Каталоги сессий также содержат исходные журналы и секреты, включая `*.secret`, `testlab-session.cfg`, `users.ini` и `server.raw.log`.

### Просмотр сохраненных результатов

Для обновления локального индекса выполните из корня репозитория на машине сервера:

```text
python tools/test_server/test_server.py results
```

Откройте возвращенный `index_path`, обычно `out/manual-tests/index.html`. Страницы, фильтры и поиск работают локально без веб-сервера. Индекс включает отчеты сценариев и сохраненные результаты smoke-проверок. Команды `report` и `smoke` обновляют его автоматически.

Для переноса коллекции скопируйте индекс, связанные HTML/JSON-результаты и очищенные журналы прогонов, сохранив относительные подкаталоги. Чтобы изменить ручную оценку, выполните `nct_result` и соберите отчет повторно. Редактирование HTML не меняет сохраненный результат.

<a id="recovery"></a>
## Восстановление и сброс

| Состояние или действие | Порядок работы |
|---|---|
| `preparing` или `running` | Дождитесь завершения. Повторный шаг при `running` возвращает `busy` |
| `failed` с диагностикой `setup_failed...` | Сохраните идентификатор и отчет, исправьте указанную причину ошибки подготовки, затем выполните `nct_repeat` |
| `canceled` | При необходимости сохраните отчет. Команда `nct_repeat` остается доступной |
| `nct_reset round` | Дождитесь сброса. Идентификатор завершенного прогона сохраняется в `last_run`; для подготовки сцены выполните новый `nct_run` |
| `nct_reset map` | Сначала сохраните идентификатор и результат. После перезагрузки карты и выбора команды/класса выполните новый `nct_run` |
| `nct_map cs_office` или `nct_map de_dust2` | Сначала сохраните текущий результат. После входа на новую карту выполните `nct_resume` в течение 120 секунд, чтобы выполнить сохраненный запрос на запуск `radar_lifecycle` |
| `nct_repeat` для `radar_lifecycle` | Карта перезагружается. После входа выполните `nct_resume` в течение того же срока |
| Ручная проверка переподключения | Сохраните результат, выполните `disconnect`, подключитесь заново, выберите команду и класс, затем начните новый прогон |
| Проверка видимости установленной бомбы | Осматривайте шаги без длительных пауз. Таймер бомбы составляет 90 секунд; взрыв или разминирование во время ожидания могут привести к ошибке сцены |

При загрузке карты поле `last_run` очищается. До смены карты сохраните идентификатор отдельно. Очистку серверного состояния и визуальный сброс фиксируйте раздельно.

Вспомогательные команды, включая возрождение, смерть, неуязвимость и перемещение, приведены в [справочнике команд клиента](../../tools/test_server/README.ru.md#client-commands).

<a id="hostage-follow"></a>
## Проверка смены источника координат заложника

В `radar_hostage_follow ct` оператор остается в `viewer_open`. Заложника ведет отдельный управляемый игрок CT. Перемещение оператора более чем на 8 игровых единиц завершает прогон ошибкой. Для наблюдения за дальним участком включите режим полной карты.

Четыре шага проверяют следующие переходы:

| Шаг | Необходимые серверные подтверждения | Визуальная проверка |
|---|---|---|
| Начало сопровождения через Use | PVS `inside` и `original_pack=1` непрерывно в течение 0,5 секунды | Один маркер выбранного заложника |
| Движение по `hostage_follow_out` | PVS `outside` и `original_pack=0` непрерывно не менее 6 секунд, не менее 3 периодических сообщений `HostagePos` оператору и не менее 256 игровых единиц перемещения по переданным координатам | Один маркер продолжает двигаться вне PVS |
| Движение по `hostage_return` | PVS `inside` и `original_pack=1` непрерывно в течение 0,5 секунды во время возвращения | Маркер возвращается к координатам из снимков сущности без скачка к устаревшей позиции |
| Остановка сопровождения через Use | Связь заложника с ведущим игроком очищена | Маркер останавливается |

В конце маршрута также проверяется, что заложник продолжает следовать за CT, приблизился к его ногам на расстояние менее 80 игровых единиц, а сервер передал оператору периодическое сообщение `HostagePos`. Идентификатор выбранного заложника определяется по реальному сообщению, если координаты сообщения совпали с координатами только одного заложника. В отчете сохраняются этот идентификатор и `native_hostage_id`.

В отчете используйте проверки `hostage_follow_inside`, `hostage_follow_outside` и `hostage_follow_return`. Ход сопровождения находится в `data.hostage_follow`. Координаты маршрутов заданы в [cs_office.ini](../../plugins/nextclient_testlab/maps/cs_office.ini).

<a id="calibration"></a>
## Калибровка видимости и маршрутов

Опорная точка (anchor) задает именованную позицию и направление взгляда в профиле карты. Калибровка требуется при ошибке проверки hull, LOS или PVS. Проверка hull определяет, нет ли препятствий в объеме размером с игрока и на пути его перемещения.

Исходные профили: [cs_office.ini](../../plugins/nextclient_testlab/maps/cs_office.ini) и [de_dust2.ini](../../plugins/nextclient_testlab/maps/de_dust2.ini). Установленные профили находятся в `<server.root>/cstrike/addons/amxmodx/configs/nextclient_testlab/maps/`. Хеш BSP в профиле должен соответствовать карте. Несовпадение останавливает подготовку до перемещения игроков и объектов сцены.

1. Сохраните идентификатор ошибочного прогона и отчет. Для проверки видимости оставьте объект сцены доступным для проверки и дождитесь `ready`. Для калибровки маршрута сопровождения выполните `nct_reset round` и дождитесь завершения сброса.
2. В консоли клиента включите запись событий и перейдите к нужной точке:

   ```text
   nct_trace on
   nct_goto viewer_occluded
   nct_noclip on
   ```

3. Скорректируйте позицию вручную. Выберите свободный участок пола и выполните `nct_noclip off`. Для проверки видимости выполните `nct_view occluded` из новой позиции, подождите три секунды и получите [снимок диагностики](#diagnostics).
4. Сопоставьте `data.visibility` с требованиями к позиции:

   | Позиция | LOS | PVS |
   |---|---|---|
   | `open` | `clear` | `inside` |
   | `occluded` | `blocked` | `inside` |
   | `outside` | Согласно профилю | `outside` |

5. Выведите новую позицию в консоли клиента:

   ```text
   nct_anchor viewer_occluded
   ```

6. На машине сервера замените секцию этой точки в установленном INI-файле полученными данными. `nct_anchor` выводит позицию, направление взгляда и фактический хеш карты; файл эта команда не изменяет.
7. Начните новый прогон, пройдите все стадии и повторите вариант пять раз. Для observer повторите проверку в том режиме камеры, который используется в данном варианте.

Если подготовка завершилась ошибкой до `ready`, сначала сбросьте сцену и исправьте указанную точку. Перед измерением видимости объекта начните новый прогон. Отрезки маршрута сопровождения должны обходить препятствия. При подготовке проверяются свободные объемы и отрезки маршрута; во время прогона проверяются перемещение игрока, движение заложника и PVS неподвижного оператора.

Во время подготовки, сброса или выполнения шага `nct_goto` возвращает `busy`. Между шагами используется профиль, уже загруженный для текущего прогона. Изменения файла применяются при новой подготовке сцены. Пересборка плагина сохраняет существующие секции установленного профиля для того же BSP и добавляет недостающие.

Для получения заготовки координат остановите сервер ручной проверки и выполните из корня репозитория:

```text
python tools/test_server/test_server.py calibrate --map cs_office
```

Команда самостоятельно запускает и останавливает сервер, затем возвращает путь к заготовке в `paths.reports`. Перед переносом откалиброванных точек в профиль проверьте их с подключенным клиентом.

После завершения проверок остановите сервер из корня репозитория:

```text
python tools/test_server/test_server.py stop
```
