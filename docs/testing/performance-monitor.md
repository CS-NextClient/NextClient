# Performance monitor runtime checks

[Russian translation](performance-monitor.ru.md) | [Operation](../performance-monitor.md)

The developer runs these checks in the game. Record revision, platform, driver, renderer, `cl_perf`, `cl_perf_gpu`, `cl_perf_scale`, FPS cap, VSync, GPU timer bits, trace connection, and `perf_dump` for each comparison. Compare monitoring disabled, CPU monitoring, GPU monitoring, and an attached diagnostic capture using the same scene and settings.

## Frame lifecycle and capture

| Case | Required observation |
|---|---|
| Host frame abort | Disconnect or reconnect after a server-triggered `Host_EndGame`, then request `perf_dump`. Studio/Radar and Host measurements continue. An abort during a capture discards its open CPU/GPU scopes and retries the next complete accepted Host, without publishing partial timings. Repeat with `cl_perf 0`, batching, and an attached diagnostic viewer. Install matching `next_engine_mini.dll` and `nitro_api2.dll` with `NITRO_FRAME_LIFECYCLE_001`. |
| Chronological frame slots | Generate multiple outputs inside one Host: each output gets a separate slot, with Host and its CPU parts present once at the last output. A Host without an output gets its own slot; a standalone output has no Host value. Check the same chronological positions in grouped and individual plots. Pending or missing GPU data leaves its output slot empty; a late result fills the original output slot without moving to the newest frame. |
| Repeated GPU replies | Validate retained output/frame/context keys, expiration, reset and ring-slot overwrite. Repeated or duplicate identifiers retain first-match semantics and cannot update an overwritten or expired record. |
| On-demand CPU capture | With cl_perf 0 and batch levels 0/1/2, perf_dump measures exactly the next complete accepted Host frame and prints automatically. Rejected/nested invocations do not finish it. Settings remain unchanged; disabled-mode capture allocates no GPU queries. Duplicate requests do not restart it. Reset/map/shutdown cancel it. Averages in the saved dump use a single frame. The current batching table continues updating independently. Compare the same scene between requests and during capture. |
| Context replacement | Query names from an old context are not deleted or closed against a new context; same-context resizing preserves them. |
| Normal and developer-controlled fatal exit | Producers stop before targets disappear, worker shutdown completes, and cleanup does not wait for GPU completion or viewer connection. |

|---|---|

Cycle every mode, change the cvars through the console, and confirm the captions follow the actual values. Reload each shipped theme, including Source: normal, hovered, pressed and disabled buttons must remain readable on opaque backgrounds. Loading and the material editor hide the group; returning to the menu restores it. |
| Grouped durations | Check overlaid Swap Interval and Host Frame columns on CPU, and Render on GPU, with stacked measured parts. Studio/Radar/Swap stack bottom to top on CPU; Studio/Radar stack bottom to top on GPU. Each physical pixel holds one chronological frame slot, with common slot order and duration scale on CPU/GPU. Adjacent frames with different durations remain separate columns. Parts belong to the same Host or output as the parent measurement. CPU/GPU use filled columns with horizontal upper edges at each frame's own duration. Missing values remain empty in their slots. Axis, grid and background match the full frame band. Stack parts share horizontal boundaries within their frame column at fractional scales and remain inside their own parent as neighboring values or part availability change. Duration-table p99 appears after 100 valid samples per series within the current N-frame window. Nested radar queries count once in Radar while retaining diagnostic detail. |
| History warmup | After perf_reset, new CPU/GPU frame slots appear on the right and shift earlier slots left. Modes 1/2/3 show History followed by last N frames. N follows the physical timing-plot width of that panel; numeric mode 1 uses its own narrower panel. Tables and plots use the same latest N slots. During warmup, available valid measurements inside those slots contribute. Change scale and resolution to check N and the matching tables. At low FPS, retained N slots can span more than ten seconds. Network windows fill independently as packets or incoming sequence slots arrive. |
| Frame-window statistics | Check avg/p99/max and Monitor CPU against valid measured values in the current N slots. Missing, pending and inactive values are excluded. A spike outside N affects neither tables nor graph scales. p99 is unavailable with 99 valid values and available with 100 inside the current window, independently of older samples. Change width to shrink and expand N and check the selected values. Panel timing history follows record count at low FPS; diagnostic perf_dump history summaries and dump FPS use their separate ten-second window. |
| Backing opacity | Change cl_perf_background_alpha between 0, 0.2 and 1 with modes 1/2/3, standalone batching/network/map inspection and combined panels. Main and graph backdrops change immediately; text, series and header accents retain their colors. |
| Shared visual style | Check modes 1/2/3, batching levels 1/2, standalone network/map inspection, and their combined display. Section titles share the same accent and background; tables use the same header background and column alignment. Summary and footer separators remain visible. Series and capacity colors retain their meaning. Numeric mode shows the CPU/GPU hierarchy with avg/p99/max. Verify short windows and different scales without clipped required network rows. |
| Main menu and `hud_draw 0` | Panel draws at main-window presentation independently of HUD drawing. |
| FPS cap and VSync | Check that header FPS follows the last 0.5 seconds at a 250 ms refresh cadence while duration tables use the current N-frame window and dump FPS uses its separate ten-second diagnostic history. Batch headings distinguish count totals from timing averages, and Calls total is the window sum. Swap Intervals include pacing; Swap CPU describes the swap call without claiming its cause. |
| Window sizing | At 1600x1200, `cl_perf_scale 1` uses the selected base. Text and graph fields follow panel scale; frame and packet columns stay one physical pixel wide and N follows each plot width. The panel remains inside the window. |
| Column pixel grid | Visually inspect CPU/GPU and network columns in the installed game at fractional scales. Every column occupies one physical pixel; N equals the plot width. A 423-pixel plot has 423 positions. Adjacent filled positions touch, while unfilled or missing values leave empty slots. The axis and tick labels sit at the left edge; the background and grid span the plot width. Tables use the same frame or packet windows as their plots. Check loss/choke markers against the packet grid. Compare adjacent CPU/GPU frames of different durations and check each column against its own duration. |

## Automated coverage

`NITRO_FRAME_LIFECYCLE_001` provides host-thread `Subscribe(observer)` and `Unsubscribe(id)` operations. Each explicit registration receives its own monotonically increasing nonzero ID, including duplicate observer pointers. A null observer returns zero. The subscriber removes its ID before destroying the observer; clearing NitroApi invalidates all registrations before module unload without reusing IDs. Each Host invocation snapshots IDs. Entries and accepted notifications follow registration order; exits follow reverse order after the ordinary subscriber chain. Every callback checks that its ID is still live. New IDs participate in subsequent invocations, including nested invocations started after registration. Acceptance during an entry callback reaches only recipients whose entry has begun and reaches later recipients once they enter.

`nitro_api-tests` checks independent registrations, rejected and repeated filter results, ordering around ordinary subscribers, self-removal and target destruction at all three boundaries, clear during callbacks, duplicate pointers, stale IDs, callback additions, detach/re-register with nested invocation, and acceptance reentry during entry. The real nonlocal abort test retains the x86 engine-style jump and verifies the next Host boundary. `engine_mini-tests` exercises the production performance subscription owner: shutdown inside nested Host keeps its ID until the matching outer exit closes the trace; shutdown outside Host removes only its own ID; rebinding removes an old ID before creating a new registration. Scoped adapter destruction removes only its own ID without shutting down the monitor. Monitor shutdown remains terminal; rebinding tests registration ownership.

Automated tests verify CPU metadata at native zone emission, distinct call sites, descriptor stability, CPU/GPU scope forwarding through the monitor, and both radar scopes. Panel command-geometry tests check the touching, right-aligned pixel grid for performance/network columns and markers, horizontal CPU/GPU column tops, smoothed network edges, empty missing-data positions, shared horizontal stack boundaries at fractional scales, containment inside parent frame values, and filled columns.

Packet tests cover independent windows whose size follows plot width, one-pixel packet columns, current-window statistics, history restoration when the window expands, sequence markers, overwritten-entry gaps, unchanged idle positions, reliable-fragment isolation and stale choke flags in lost sequence slots.

Network refresh tests preserve other sections across empty/full packet windows and update network plus batching at one presentation without refreshing CPU/GPU or mapper content. Frame-history tests verify separate adjacent frame values, common CPU/GPU slot order, Host/output ownership and late GPU results in their original output slots. Frame-window summary checks cover the shared N for plots/tables/scales, low-FPS retention, excluded states and percentile availability inside the current window.

Automated suites also cover pure accounting/history, lifecycle state transitions, SDL calling conventions and frozen offsets, shared-client identity across DLLs, bounded query reservations, actual GL timestamps, and GL-state restoration around panel drawing and measured submissions. The panel GL test uses a test font provider with real texture uploads. Check Windows font appearance in the installed game. Radar GL tests exercise actual radar passes separately. A capability skip is not a successful GPU timing measurement.

Record game observations separately from compilation, fake-backend tests, and offscreen GL results. Live-game checks establish callback ordering, appearance, and collection overhead for the selected hardware and scene.
