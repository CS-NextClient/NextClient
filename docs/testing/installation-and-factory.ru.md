# Проверки установки и фабрики поставляемой библиотеки

[Английская версия](installation-and-factory.md) | [Указатель проверок](README.ru.md)

Эти проверки выполняются перед установкой измененного комплекта модулей. Они проверяют установку во временные каталоги и интерфейс подготовленной библиотеки NitroApi. Игра и сервер для них не нужны.

## Предварительная проверка установки

Запускайте команды из корня репозитория в поддерживаемой среде сборки x86. Стандартные пресеты Ninja используют явно выбранную конфигурацию:

```powershell
cmake --preset ninja-tests
cmake --build --preset ninja-tests-release --target verify-nitro-api-factory
ctest --test-dir build/ninja-tests -C Release -R '^(installation-preflight|nitro-api-shipping-factory.*)$' --output-on-failure
```

Проверка установки должна отклонить отсутствующее содержимое материалов, представленное указателями Git LFS, до изменения каталога назначения. При полных входных данных должны устанавливаться ожидаемые файлы платформы и библиотека профилирования, если оно включено. Повторная установка в Linux должна сохранять исходную резервную копию VGUI.

Проверки используют временные каталоги внутри каталога сборки и не устанавливают результат в игру разработчика. Успешная проверка подтверждает эти условия; восстановление после ошибки копирования операционной системы требует отдельного подтверждения.

## Проверка интерфейса собранной NitroApi

Соберите цель `verify-nitro-api-factory`. Она подготавливает библиотеку `nitro_api2.dll`, загружает ее и проверяет ожидаемую версию интерфейса отслеживания кадров. Если библиотека отсутствует или интерфейс недоступен, проверка должна завершиться ошибкой и указать причину.

Цель доступна и в конфигурациях поставляемой сборки:

```powershell
cmake --preset ninja
cmake --build --preset ninja-release --target verify-nitro-api-factory
cmake --preset ninja-profiler
cmake --build --preset ninja-profiler-release --target verify-nitro-api-factory
```

Подготовленная библиотека NitroApi, ее библиотеки времени выполнения и `manifest.sha256` находятся в `<binaryDir>/nextclient/nitro_api/factory-probe/<config>/`. Манифест определяет подготовленные файлы. Цель проверки не устанавливает их в игру.

Чтобы проверить конкретную сборку `nitro_api2.dll` в Windows, передайте утилите абсолютный путь к библиотеке:

```powershell
$prepared = (Resolve-Path 'build/ninja/nextclient/nitro_api/factory-probe/Release').Path
& 'out/bin/Release/nitro-api-factory-probe.exe' (Join-Path $prepared 'nitro_api2.dll')
```

Обычная утилита Windows находится в `out/bin/Release/nitro-api-factory-probe.exe`, вариант с профилированием в `build/ninja-profiler/out/bin/Release/`. Храните библиотеку NitroApi вместе с согласованными библиотеками времени выполнения, включая Tracy при включенном профилировании.

Для Linux:

```bash
cmake --preset linux -DNEXTCLIENT_BUILD_TESTS=ON
cmake --build --preset linux-release --target verify-nitro-api-factory
ctest --test-dir build/linux -C Release -R '^(installation-preflight|nitro-api-shipping-factory.*)$' --output-on-failure
```

В Linux библиотека NitroApi сохраняет имя `nitro_api2.dll`. Прямой запуск утилиты требует абсолютного пути к ней и каталога подготовленных зависимостей в `LD_LIBRARY_PATH` до запуска процесса.

Положительный сценарий CTest называется `nitro-api-shipping-factory`; `nitro-api-shipping-factory-missing-provider` проверяет отказ при недоступной библиотеке NitroApi. Эти проверки подтверждают доступность интерфейса подготовленной библиотеки. Поведение работающего движка, инициализация и завершение требуют отдельного наблюдения.

## Соответствие подготовленных и установленных файлов

Соберите измененные библиотеки и модули, которые используют их интерфейсы, из одной ревизии. Для всего комплекта должны совпадать платформа, пресет, конфигурация и режим профилирования. Запишите состав комплекта с абсолютными путями, размерами в байтах и SHA-256. Завершите проверки до установки, затем сопоставьте каждый установленный файл с манифестом.

Компиляция, проверка подготовленной библиотеки, установка и наблюдения в игре являются отдельными результатами. Повторно используйте действующие проверки для неизменных исходников и конфигурации. Затем выполните подходящую процедуру для [монитора](performance-monitor.ru.md), [сцены материалов](material-editor-scene.ru.md) или [Studio](studio-rendering.ru.md).
