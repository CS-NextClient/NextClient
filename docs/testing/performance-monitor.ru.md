# Проверка монитора производительности

[Английская версия](performance-monitor.md) | [Использование монитора](../performance-monitor.ru.md) | [Указатель проверок](README.ru.md)

Эти сценарии проверяют монитор в игре, запущенной разработчиком. Запишите ревизию, установленные модули, платформу, GPU и драйвер, разрешение, ограничение FPS, VSync и включенные режимы. При сравнении затрат используйте одну сцену или демо.

## Подготовка

Установите согласованный комплект модулей после [проверок установки](installation-and-factory.ru.md). Для Tracy выполните настройку из [руководства по монитору](../performance-monitor.ru.md#диагностическая-запись-tracy). Сохраняйте нужные дампы, снимки и записи вместе с каждым результатом.

## Сценарии в игре

| Действие | Ожидаемый результат |
|---|---|
| Переключите `cl_perf` между 0, 1, 2 и 3 в игре и меню. | Появляется выбранный вид, подписи читаемы, отключение основного монитора сохраняет отдельно включенные блоки. |
| Измените разрешение, масштаб панели и непрозрачность при нескольких включенных блоках. | Панели остаются в окне, разделы различимы, подписи и шкалы графиков согласованы. |
| Измените ограничение FPS или VSync в фиксированной сцене. | Монитор раздельно показывает интервалы между кадрами и время их обработки. Сводные значения графиков и таблиц рассчитаны за тот период, который сейчас виден на графике. |
| Запросите `perf_dump` при выключенном, затем при включенном основном мониторе. | В консоль автоматически выводится дамп одного кадра, обработку которого движок завершил. Настройки монитора сохраняются. По идентификаторам CPU и GPU можно определить, к каким кадрам относятся измерения. |
| Выполните сброс или смените карту при ожидающем дампе. | Ожидающий запрос отменяется. Новый запрос захватывает текущую сцену. |
| Отключитесь и подключитесь повторно, в том числе после прерывания обработки кадра. | Сбор продолжается в следующих кадрах; незавершенная работа не выдается за успешный полный кадр. |
| Сравните `cl_perf_batch` 0, 1 и 2 при `cl_perf 0`. | При значении `0` секция скрыта, при `1` видны счетчики группировки моделей, при `2` также доступны подробные измерения CPU. Основные графики остаются скрыты. |
| Включите `cl_perf_net 1`, получите трафик, приостановите трафик, затем выключите блок. | Позиции пакетов меняются с трафиком, история простоя остается понятной, штатный график возвращается с сохраненной настройкой. |
| Исследуйте локальную карту с `cl_perf_map` 1 и 2, затем подключитесь к внешнему серверу. | Локальный уровень 2 показывает свойства и контур; на внешнем сервере остаются разрешенные сведения уровня 1. |
| Используйте действие E анализа карты при игровом вводе, открытой консоли и меню. | В игре вывод выполняется один раз на нажатие с сохранением исходной привязки; ввод консоли и меню не запускает анализ. |
| Измените видеорежим и вернитесь к той же сцене. | Панель и измерения возобновляются, старая работа GPU не выдается за новый результат. |
| Подключите и отключите просмотрщик Tracy. | Трассировка следует подключению, а управление встроенным монитором остается независимым. Проверьте состояние трассировки и причину остановки в дампе. |
| Завершите клиент и запустите его снова. | Завершение проходит успешно, мониторинг новой сессии работоспособен. |

При отсутствующих или запоздавших значениях GPU проверьте, что их состояние отличается от измеренного нуля. Если значение выглядит привязанным к другому кадру, сохраните дамп и запись. Перекрывающиеся длительности и разные окна оцениваются по [руководству по графикам](../performance-monitor.ru.md#чтение-графиков).

Для сравнения производительности повторяйте один фрагмент демо с выключенным мониторингом, мониторингом CPU, мониторингом GPU и диагностическим захватом как отдельные сценарии. Сохраняйте одинаковые прогрев и настройки. Захват одного кадра и подключенный профилировщик добавляют затраты диагностики. Не используйте эти запуски для оценки скорости обычной сборки без диагностики.

## Автоматические проверки

Выбирайте проверки по измененному поведению. Настройте поддерживаемый пресет x86 с включенными тестами и отдельно соберите каждую выбранную цель перед запуском ее сценариев CTest.

| Цель | Что проверяется |
|---|---|
| `nitro_api-tests` | Определение начала, завершения и прерывания кадра. |
| `engine_mini-tests` | Сбор измерений, его остановка, диагностические снимки, сетевые данные и подготовка панели. |
| `performance-history-tests` | Статистика за выбранный период при пропущенных и запоздавших измерениях. |
| `performance-gl-tests` | Измерение времени GPU и изображение панели в отдельном GL-контексте. |
| `radar-gl-tests` | Изображение радара при включенных измерениях GPU. |
| `diagnostic-profiling-tests`, `profiling-connection-tests` | Сведения об исходном коде в записи профилировщика, подключение и отключение Tracy при `USE_PROFILER=ON`. |

Работа монитора и учет кадров описаны в [архитектуре монитора](../performance-architecture.ru.md). [Процедура проверки библиотеки NitroApi](installation-and-factory.ru.md) проверяет ее публичный интерфейс.

GL-тестам нужна подходящая графическая среда; пропущенный тест не подтверждает измерение времени GPU. Наблюдения в установленной игре подтверждают работу панели и производительность для выбранного оборудования и сцены. Результаты запуска вместе с ревизией, конфигурацией и журналами сохраняются в отчете сессии.
