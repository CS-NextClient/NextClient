# Формат материалов оружия

[Английская версия](weapon-materials.md) | [Руководство автора](weapon-materials-authoring.ru.md) | [Серверное API](weapon-materials-server-api.ru.md)

При отрисовке Studio-модели клиент подбирает материал по имени текстуры. Вне сеанса редактирования он сначала проверяет серверную привязку сущности, затем документ `.mat` модели. Если материал не задан ни в одном из этих источников, клиент использует встроенный материал по флагам текстуры. Активный сеанс редактирования временно заменяет выбранный материал для своей цели. Для материалов требуются `r_studio_shader 1` и `r_studio_materials 1`.

## Документ модели

Для `models/v_glock18.mdl` используется документ `models/v_glock18.mat`. Его объект `materials` сопоставляет имена текстур модели с материалами. Имена текстур сравниваются без учета регистра. Материал получает каждый меш с выбранной текстурой, в том числе меши других частей тела. Сначала выбранное семейство скинов определяет текстуру меша, затем клиент подбирает для нее материал.

```json
{
    "version": 1,
    "materials": {
        "glock_slide.bmp": {
            "program": "weapon_finish",
            "params": {
                "uWearMap": { "texture": "materials/masks/wear/blotches.png" },
                "uUnderlay": { "texture": "materials/surfaces/brass.png" },
                "uWear": 0.5
            }
        }
    }
}
```

Материал содержит обязательное поле `program` и необязательный объект `params`. Имена параметров должны точно совпадать с манифестом программы, включая регистр. Число задает скаляр, массив из четырех чисел задает вектор, `{"texture": "path"}` задает ссылку на изображение. Клиент проверяет типы и диапазоны значений по манифесту. Скаляры и все компоненты векторов должны быть конечными числами в объявленных границах. Пропущенные параметры получают объявленные значения по умолчанию.

## Ограничения файлов и изображений

| Ресурс | Лимит |
|---|---|
| Версия документа | `1` |
| Записи текстур в документе модели | 64 |
| Параметры одного материала | 64 |
| Различные файлы изображений, указанные в документе | 64 |
| Путь изображения в документе модели | 128 байт |
| Путь изображения в серверном пресете | 96 байт |
| Форматы изображений | PNG или TGA |
| Площадь изображения | 1 048 576 пикселей |

Пути изображений задаются относительно игрового каталога. Используются прямые слэши и расширения `.png` или `.tga`. Абсолютные пути, префиксы дисков, обратные слэши, управляющие символы и пустые сегменты, `.` или `..` отклоняются. Площадь вычисляется как `width * height`. Поставляемые изображения входят в общий лимит файлов. Повторная ссылка на тот же файл учитывается один раз.

## Манифест программы

Манифест программы объявляет `version`, `program` и `parameters`. Каждый параметр задает тип (`scalar`, `vec4` или `texture`) и может задавать значение по умолчанию, границы, подпись, подсказку и элемент управления редактора. Скалярный параметр с `instance: true` допускает изменение для отдельной сущности через [серверное API](weapon-materials-server-api.ru.md#нативы). Сервер передает конечный `Float:value` в единицах параметра. Клиент сохраняет точность float и ограничивает значение объявленными границами. Обычный скаляр не требует шага или кратности.

Необязательное поле `render_contract` содержит непустую строку длиной не более 64 байт. Значение копируется в манифест. Поле расширяет версию манифеста `1`. Пакет материалов проверяет только формат поля. При отсутствии поля параметры программы остаются универсальными. Движок публикует манифест, только если его имя совпадает с запрошенной встроенной программой, оба исходника шейдеров встроены в модуль, а контракт принят рендерером.

Встроенные манифесты `studio` и `weapon_finish` объявляют `"render_contract": "studio_effects_v1"`. `render::StudioProgramContract` задает роли прозрачности, альфа-канала базового цвета, обводки, скрытых участков и свечения: типы, диапазоны, значения по умолчанию, свойство `instance`. Подписи, группы и оформление редактора остаются в манифестах. Две ограниченные активации, `uOccludedAmount` и `uOutlineWidth`, допускают конечное значение по умолчанию в фиксированном диапазоне. Остальные семантические значения по умолчанию должны точно соответствовать профилю. Для добавления встроенной программы с этим профилем нужны пара шейдеров, регистрация встроенных ресурсов и совместимая декларация манифеста. Прозрачность, выбор мышью, эффекты и серверная политика используют профиль без дополнительной регистрации имени программы.

Схема допускает 64 параметра, в том числе восемь текстурных. Необязательный массив `groups` задает разделы редактора. Поле `strings` указывает файл локализации. Точные значения по умолчанию, границы и группировка элементов редактора приведены в поставляемом [манифесте `weapon_finish`](../nextclient/engine_mini/assets/shaders/weapon_finish.json).

Скалярный параметр с `widget: "choice"` задает массив локализованных подписей `choices`. Значениями служат целые индексы: `min: 0`, `max: choices.size()-1`. Значение `default` тоже должно быть целым индексом из этого диапазона. Редактор показывает список без свободного ввода. Дробные индексы отклоняются до ограничения границами; целые индексы за границами ограничиваются диапазоном при записи через API. Например, у `uOutlineMode` индекс `0` включает обводку только скрытых участков, `1` включает весь силуэт, а `2` только видимые участки.

## Параметры `weapon_finish`

| Параметр | Назначение |
|---|---|
| `uBaseTint` | Множитель цвета базовой текстуры. |
| `uPattern`, `uPatternTint`, `uPatternTransform` | Изображение узора, оттенок и размещение по UV. Альфа узора также управляет смешиванием. |
| `uLayerMix` | Доля узора, `0..1`. |
| `uWearMap`, `uWearMapTransform` | Пороговая карта и размещение по UV. Темные участки стираются первыми. |
| `uWear` | Степень износа, `0..1`. |
| `uWearSoftness` | Половина ширины перехода около порога износа. |
| `uUnderlay`, `uUnderlayTint`, `uUnderlayTransform` | Изображение обнажаемой поверхности, оттенок и размещение по UV. |
| `uReflectMask`, `uReflectMaskTransform` | Множитель силы отражения и размещение по UV. |
| `uReflectTint` | Множитель цвета блика от света сцены и отражения из matcap. |
| `uReflectWear` | Зависимость блеска от износа: от `-1` для покрытия до `1` для обнаженных участков; при `0` действует одна маска. |
| `uSphereMap`, `uReflectivity` | Изображение освещенной сферы (matcap) и сила отражения. |
| `uSpecular`, `uGloss` | Сила и показатель степени блика от света сцены. |

UV-преобразования задаются как `[scale_u, scale_v, offset_u, offset_v]`. Шейдер смешивает узор с базовой текстурой, применяет порог износа через `smoothstep`, подмешивает обнажаемый слой, затем добавляет к освещенной поверхности блики с учетом маски. Блик использует прямое освещение, отражение из matcap использует общий уровень света.

Разбор и проверка реализованы в [`ncl_material`](../nextclient/packages/ncl_material/include/ncl_material/MaterialDoc.h). [Справочник рендерера](renderer-architecture.ru.md) описывает привязку текстур, GL-ресурсы и порядок отрисовки.
