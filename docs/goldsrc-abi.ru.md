# Инструменты сопровождения ABI GoldSrc

[Английская версия](goldsrc-abi.md) | [Интеграция движка](nitro-api.ru.md)

ABI определяет, как скомпилированные модули обмениваются данными и вызывают функции друг друга. В NextClient инструменты ABI проверяют описания типов GoldSrc и создают по ним заголовочные файлы. Поддерживается 32-битная сборка движка 8684. Правила изменения исходников находятся в [инструкциях модуля](../nextclient/goldsrc_abi/AGENTS.md).

## Начало работы

Используйте Python 3 из корня репозитория:

```text
python nextclient/goldsrc_abi/tools/library.py check
```

Команда сообщает о проблемах, не перезаписывая заголовки. Исправьте ошибки проверки до генерации. Совместимость с другой сборкой движка требует собственных проверенных данных.

## Входные данные

Генератор использует проверенные факты Windows и Linux и карту заголовков из `nextclient/goldsrc_abi/tools/`. Вместе с фактами сохраняются ревизии исходников и идентификаторы бинарных файлов.

Часть заголовочных файлов дополнена вручную. Генерация прямо в каталог исходников может затереть эти дополнения. Сначала создайте файлы в отдельном каталоге и сравните их с файлами проекта.

### Источники Linux x86

В [facts_linux.json](../nextclient/goldsrc_abi/tools/facts_linux.json) хранятся данные о типах штатного движка Linux x86, сборка 8684. Они дополняют [общие данные](../nextclient/goldsrc_abi/tools/facts.json), по которым создаются заголовочные файлы NextClient. Перед обновлением проверьте, из каких исходников и библиотек получены эти сведения.

Входные данные фиксируют ревизии NextClient, NitroApi и SDK, использованные при извлечении. Сохраняйте записанные идентификаторы при проверке или воспроизведении данных.

| Штатный бинарный файл | SHA-256 |
|---|---|
| `hw.so` | `1e775773292407106ac17c98bc19f0444e8f1525d46e592de5cc53afad2b89e1` |
| `cstrike/cl_dlls/client.so` | `40283f3e0c4b6bd21f9281304957ab93c04c60ce5f3d2794cdaf58b3c11ab798` |

Движок и клиент являются независимыми источниками. Данные другой библиотеки или платформы требуют проверки перед заменой существующего факта. Совпадение имени само по себе не подтверждает совместимость.

Перед генерацией проверьте данные и замечания к ним. Затем выполните [генерацию и сравнение файлов](#генерация). Все обнаруженные ошибки нужно разобрать до замены заголовков проекта.

Команды извлечения, журналы компиляторов и результаты проверок сохраняйте в отчете вместе с версиями исходников и хешами библиотек. Успешная проверка заголовков не заменяет проверку работы клиента в игре.

## Генерация

```text
python nextclient/goldsrc_abi/tools/library.py check
python -m unittest discover -s nextclient/goldsrc_abi/tools -t nextclient/goldsrc_abi/tools -p "test_*.py"
python nextclient/goldsrc_abi/tools/library.py headers --out build/abi-review/include
python nextclient/goldsrc_abi/tools/library.py tests --out build/abi-review/tests
```

При необходимости используйте `python3`. Каталог сравнения должен находиться внутри репозитория, чтобы форматирование использовало настройки проекта. При сравнении результата записывайте версию форматтера. Генератор может удалить из выходного каталога файлы, отсутствующие в модели; используйте отдельный каталог вывода.

Проверьте добавление и удаление файлов и изменения содержимого. Сохраните сопровождаемые дополнения, затем скомпилируйте проверки совместимости в настроенной сборке x86:

```text
cmake --build --preset vs2022-release --target goldsrc_abi_golden
```

Проверка выполняется при компиляции. Также соберите NitroApi и модули, использующие измененные заголовки, на каждой затронутой платформе. Работу в игре проверяйте отдельно.

## Зафиксированные пути извлечения

В исходных данных сохранены пути к файлам той версии проекта, из которой получены описания типов. Эти пути могут отличаться от текущих. Сохраняйте их, чтобы можно было найти и проверить исходный материал. Для повторного извлечения используйте соответствующую версию исходников и отдельный выходной файл.

## Проверка происхождения

Полная подготовка описана в [процедуре сборки](../.github/workflows/build.yml). Запросите CMake File API `codemodel-v2` до конфигурации и запустите проверку после сборки:

```text
python nextclient/goldsrc_abi/tools/provenance.py --build-dir build/vs2022 --config Release --allowlist .github/provenance-allowlist.json --report build/provenance-report.json
```

Проверьте отчет на неожиданные зависимости и сохраните его вместе с конфигурацией сборки. После изменений исходников или графа сборки повторите конфигурацию. Не расширяйте список разрешений только ради прохождения новой зависимости; рассмотрите само изменение зависимости. Отчет проверяет происхождение исходников и зависимости сборки, а не юридический статус бинарного файла.
