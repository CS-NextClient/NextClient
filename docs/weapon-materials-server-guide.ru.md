# Применение серверных материалов

[Английская версия](weapon-materials-server-guide.md) | [Справочник API](weapon-materials-server-api.ru.md) | [Руководство автора](weapon-materials-authoring.ru.md)

Для передачи серверных материалов нужны AMX Mod X и серверный модуль NextClientServerApi. Поддерживаемые операции описаны в [справочнике API](weapon-materials-server-api.ru.md).

## Доставка и привязка материала

1. Создайте пресет по [описанию формата](weapon-materials-server-api.ru.md#формат-пресета) и сохраните его как `materials/my_server/skins.mat`.
2. Поместите пресет в игровой каталог клиента. Без подключения к серверу выполните `r_mat_presets materials/my_server/skins.mat` и проверьте в консоли сообщения об ошибках загрузки и исключенных материалах. Отдельно проверьте изображения по [ограничениям формата](weapon-materials.ru.md#ограничения-файлов-и-изображений).
3. Зарегистрируйте пресет и каждое пользовательское изображение через `ncl_upload_file` в `plugin_precache`. Для файлов `.mat`, `.png` и `.tga` и серверный, и клиентский путь должны находиться внутри `materials/`. Изображения поставляемой коллекции уже установлены с клиентом.
4. Привяжите материал к оружию, затем задайте параметры экземпляра конечными значениями float.

На совместимом клиенте с включенными шейдерами и материалами назначенный материал появляется на соответствующей текстуре модели. Имя текстуры в пресете должно совпадать с именем текстуры модели.

## Если материал не отображается

1. Проверьте, что установленный клиент поддерживает это API материалов и использует `r_studio_shader 1` и `r_studio_materials 1`.
2. Проверьте, что пресет получен по тому же относительному пути, который передан в `ncl_mat_bind`.
3. Проверьте имя материала в пресете и имя текстуры модели. Список текстур модели доступен в редакторе материалов.
4. Проверьте журнал серверного модуля на ошибки аргументов нативов, а консоль клиента на ошибки загрузки пресета и несовместимость с манифестом. После изменения пресета отключитесь от сервера, выполните `r_mat_presets clear`, затем загрузите его командой `r_mat_presets <preset.mat>`. Изображения отдельно проверьте в редакторе материалов.
5. Проверьте привязки загруженного клиента командами из таблицы.

Изменения через `r_mat_bind`, `r_mat_param` и аргументы `r_mat_presets` разрешены только отключенному клиенту. В сетевой игре подкраска и обводка включаются явными серверными параметрами экземпляра `uOccludedAmount` и `uOutlineWidth`, как описано в [эффектах материалов](material-effects.ru.md).

| Команда | Действие |
|---|---|
| `r_mat_presets [file\|clear]` | Вывести пресеты в кеше, загрузить пресет или очистить кеш пресетов и все клиентские привязки материалов. |
| `r_mat_entities` | Вывести индексы и имена моделей из следующих 64 отрисованных сущностей, пропуская повторные индексы. |
| `r_mat_bind` | Вывести привязки; `(never drawn)` отмечает индекс, к которому рендерер не обращался. |
| `r_mat_bind <entity> <preset> <material>` | Применить локальную диагностическую привязку. |
| `r_mat_bind <entity>` | Очистить локальные привязки этого индекса. |
| `r_mat_param <entity> <name\|texture/name> <value>` | Задать параметр экземпляра для всех подходящих материалов или одной указанной текстуры. |

Консольные команды предназначены для локальной проверки. Они имеют приоритет над серверными назначениями для той же текстуры. Обновление параметров с сервера может заменить локальные изменения. У одной сущности одновременно используются материалы не более чем для 16 разных текстур; при достижении лимита удалите ненужные локальные привязки. Снимки изображения и дампы помогают проверить, какой материал отображается; см. [диагностику Studio](renderer-diagnostics.ru.md).

## Передача основной текстуры для замены

В пресете `studio` или `weapon_finish` укажите в `uBaseTexture` PNG/TGA под `materials/` и зарегистрируйте изображение через `ncl_upload_file` вместе с пресетом. Значение `uBaseUvMode: 0` использует исходные размеры развертки модели, а `1` использует размеры внешнего изображения. Привяжите пресет к исходному имени текстуры MDL, сохранив начальный `#`, если он есть. Отдельная серверная команда для этих параметров пресета не требуется; правила прозрачности и возврата к исходной текстуре описаны в [справочнике материалов](weapon-materials.ru.md#замена-основной-текстуры).

## Перчатки игрока и оружия

Дополнительная библиотека `next_client_gloves.inc` в NextClientServerApi позволяет задавать перчатки игроку и отдельному оружию через стоки поверх нативов материалов. Профиль оружия имеет приоритет; его сброс возвращает выбор текущего владельца. Требуются ReAPI с ReGameDLL и Fakemeta. Библиотека применяет только итоговый профиль активного оружия.

Используйте `ncl_gloves_set_player`, `ncl_gloves_set_weapon` и соответствующие стоки сброса. [Руководство по API перчаток](https://github.com/CS-NextClient/NextClientServerApi/blob/main/docs/gloves.ru.md) описывает регистрацию профилей, доставку ресурсов, подключение к событиям плагина и готовый пример. Имена текстур рук должны соответствовать каждой модели; другие плагины не должны независимо назначать материалы тем же текстурам рук.
