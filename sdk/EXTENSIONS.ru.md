# Интерфейсы расширений SDK 1.0

SDK 1.0 предоставляет эти интерфейсы через ABI 1/API 1 для Windows 10+ **x86**.
Включение, отключение, изменение порядка и обновление пакетов требуют перезапуска.
Интерфейсы не предоставляют произвольные перехваты движка, достоверные серверные
данные, которые клиент не получает, 3D-рендеринг, выгрузку без перезапуска
или изоляцию нативного кода.

## Общий ABI

`NcHost::query_interface(context, name, 1)` возвращает таблицу `NcExtension`
или null для неизвестного имени или версии. Перед использованием проверьте
`size` и `version`. Версии интерфейсов согласуются независимо от раскладки
`NcHost`. Плагины могут использовать эти таблицы вместе с основными вызовами
хоста и обработчиками событий.

`call(context, operation, json)` копирует аргумент-объект и выполняет операцию
**один раз**. Он возвращает дескриптор результата, доступный только владельцу.
`read_result` возвращает требуемый размер буфера UTF-8 с NUL и копирует данные,
только если места достаточно. Повторное чтение не выполняет операцию повторно.
После чтения всегда вызывайте `release_result`. Ноль означает, что вызов отклонён
до передачи операции: неверный поток, отключённый из-за ошибки плагин или лимит
неосвобождённых результатов. Операции возвращают `{"ok":true,...}` или
`{"ok":false,"error":"..."}`; обёртки SDK возвращают этот JSON без изменений.
Входные данные ограничены 64 КиБ и глубиной вложенности 16. Освобождайте результаты
сразу после использования: на плагин допускается не более 64 неосвобождённых
результатов, а их общий объём ограничен. Дескрипторы не используются повторно
в рамках процесса и не дают доступа к результатам другого владельца.

C++ (подкласс `nextclient::Plugin`):

```cpp
auto json = extension("nextclient.events", "stats");
auto commit = extension("nextclient.storage", "commit",
                        R"({"set":{"total":42},"delete":["temporary"]})");
```

Rust (связующий код на C++ и внешний крейт не нужны):

```rust
let api = host.query_interface("nextclient.events", 1).ok_or(nc::Error)?;
let stats_json = api.call("stats", "{}")?;
host.console_print(&stats_json)?;
let store = host.query_interface("nextclient.storage", 1).ok_or(nc::Error)?;
let accepted = store.call("commit", r#"{"set":{"total":42}}"#)?;
// Parse accepted.ok and accepted.request using your preferred JSON parser.
```

Все таблицы используют единый C ABI и схемы JSON в UTF-8. `Extension` в Rust
заимствован и не реализует Send/Sync. Для рабочих потоков безопасна только функция
отправки, описанная ниже. Перед выходом из unload дождитесь завершения всех
рабочих потоков плагина.

## События, задачи и хранилище

`nextclient.events/stats` возвращает счётчики очереди, доставки и потерь,
`callback_ms`, накопленный `slow_callbacks` (дольше 2 мс) и карту `callbacks`:
число вызовов, последнее, максимальное и суммарное время для **всех** категорий,
включая инициализацию, завершение, выгрузку модуля, кадр, рисование, команды и фильтры сообщений.
`deferred_callbacks` считает допустимые обработчики, пропущенные из-за лимита
времени или числа событий, в том числе отдельных проходов по 2 мс. Событие,
ожидающее несколько кадровых опросов, учитывается на каждом; проверка бюджета
без готового обработчика не увеличивает счётчик.
Оценка памяти хоста и время обработчиков доступны только на вкладке **«Диагностика»**
в режиме разработчика (`developer 1` в консоли). Выбор вкладки или другого плагина
обновляет снимок статистики; `developer 0` скрывает вкладку. Обновление читает
текущую статистику из памяти без повторного обнаружения и хеширования пакетов.
Ограничения ресурсов и статистика SDK действуют в обоих режимах.

Общий бюджет учёта для всех плагинов — 32 МиБ; обычные сохраняемые ресурсы занимают
не более 30 МиБ, оставляя резерв для чтения результатов и разбора JSON. Учитываются
ёмкость контейнеров, узлы JSON, накладные расходы, хранилища, описания UI, результаты,
очереди, копии записей и резерв завершения запросов. Разбор JSON и чтение пакетов
также требуют временного резерва. Поля `host_memory_estimate`, `host_memory_limit`,
`host_memory_peak`, `memory_rejections` доступны в статистике. Это консервативная
оценка, **не измеренная память процесса**. Образы DLL, нативные выделения плагинов,
память драйверов и отдельные синхронные вызовы нельзя надёжно ограничить квотами SDK.
Операция может быть отклонена раньше индивидуального лимита; обрабатывайте ошибки
и своевременно освобождайте результаты.

У каждого плагина остаётся очередь на 2 048 событий / 1 МиБ JSON. Поочерёдная
доставка использует **общий лимит 2 мс / 512 событий за кадр**; не более 128 событий
на владельца, включая сообщения о потерях. Обработка кадров и рисование имеют
по 2 мс на общий проход с чередованием первого владельца. Результат рисования
накапливается в буфере, затем успешные результаты выводятся в порядке загрузки,
сохраняя порядок слоёв HUD после превышения срока вызова. Все автоматические
категории делят мягкий бюджет 6 мс между кадровыми опросами. Каждая категория
(события, кадры, рисование, команды, фильтры) резервирует один вызов на опрос
с чередованием приоритетного владельца, даже если другая категория исчерпала бюджет.
Выбранные команды и фильтры по-прежнему выполняются в настроенном порядке.
Это исключение для продвижения каждой категории и уже начатые вызовы, которые
невозможно прервать, могут превысить бюджет. Остальные команды и фильтры при
исчерпании бюджета пропускаются. Пропущенные кадры и рисование не воспроизводятся
позднее; события остаются в очереди с учётом её лимита и разрешений.
Явные действия, изменения настроек, консольные команды и жизненный цикл
измеряются, но не отбрасываются по кадровому сроку. Новые события при доставке
ждут следующего кадра; события без подписки не сохраняются.

При переполнении новые события отбрасываются, а `sdk.overflow` доставляется
в обход очереди с накопленным `dropped` и номерами `first`/`last` потерянных событий
с прошлого отчёта. Это глобальные порядковые номера постановки в очередь;
диапазон может включать события для других плагинов. Доставка ограничена,
это не журнал без потерь. При переполнении обновите снимки и сбросьте расчёты,
которым нужна полная история событий.

`nextclient.tasks/token` возвращает непрозрачный `token`. Функция таблицы
`post(token,json)` копирует данные из любого потока и доставляет `sdk.task`
владельцу в игровом потоке. Она возвращает 0, если токен недействителен,
очередь заполнена или останавливается. Токены становятся недействительными
при сбое или выгрузке плагина и не используются повторно. Общая очередь отправки
ограничена 1 024 сообщениями / 1 МиБ. В Rust `api.post_token(token)` возвращает
`PostToken`, реализующий Send/Sync. Каждый владелец может поставить в очередь
не более 64 сообщений / 128 КиБ. В C++ можно сохранить указатель на функцию
и токен без сохранения `NcHost` в рабочем потоке. `post(token, nullptr)` в C
проверяет токен без отправки: 1 — активен, 0 — остановить работу. В Rust используйте
`PostToken::is_cancelled()`. Проверяйте его в рабочих циклах; отмена кооперативная.
Сбой немедленно прекращает SDK-активность, отменяет ожидающие задания хоста и
освобождает очереди, результаты, хранилища и описания UI. Начатая дисковая запись
может завершиться. DLL и контекст сохраняются до завершения клиента; `unload`
обязан дождаться рабочих потоков. Это относится и к неудачной частичной
инициализации. Не откладывайте реакцию на отмену до `unload`.

`nextclient.storage/commit` принимает `{"set":{...},"delete":[...]}`.
Рабочий поток хоста обновляет JSON-хранилище плагина одной атомарной транзакцией.
Ответ содержит `request`. После завершения `sdk.storage` сообщает
`{"request":N,"ok":true}` или `ok:false`. У плагина может быть только одна
незавершённая транзакция; одновременные синхронные и асинхронные изменения
отклоняются, включая удаление ключа, которого нет в зафиксированном снимке.
Чтение возвращает последний зафиксированный снимок, пока основной
поток не обработает завершение. Принятые записи завершаются до остановки;
ошибка записи сохраняет предыдущее состояние хранилища. Синхронное и асинхронное
сохранение используют общие ограничения: 1 024 ключа, 64 КиБ на значение
и 1 МиБ всего. Уведомления о завершении используют общую очередь событий;
после переполнения перечитайте хранилище, прежде чем делать вывод о результате
транзакции.

Уведомления `sdk.*` адресуются хостом конкретному плагину и не требуют обычной
подписки на события. Плагин не может опубликовать событие хоста через посредник
сервисов.

## Сообщения сервера и фильтры отображения

Запросите `messages.read`, чтобы использовать `nextclient.messages/subscribe`
или `unsubscribe` с `{"name":"CustomMsg"}`. Имена состоят из 1–15 ASCII-букв,
цифр или подчёркиваний; допускается до 128 имён на плагин. Сообщение доступно только
после регистрации его обработчика через обёрнутую таблицу движка штатного клиента
или client_mini. Подписка до такой регистрации либо на сообщение, зарегистрированное
только через другую таблицу движка, возвращает
`{"ok":false,"error":"Message hook unavailable"}`. Регистрация фильтра для недоступного
сообщения возвращает 0. При необходимости повторите запрос после регистрации
обработчика. Запросы подписки не регистрируют и не заменяют обработчики движка.
Регистрации через другие таблицы не наблюдаются; замена обёрнутого обработчика
через такую таблицу прекращает наблюдение. Пользовательские сообщения,
зарегистрированные через обёрнутую таблицу, не требуют изменения списка событий моста.

`sdk.message` содержит `name`, `bytes` (массив беззнаковых байтов), клиентское
`time` и серверную `epoch`. Данные больше 4 096 байт игнорируются. Байты копируются
до фильтров и исходного обработчика HUD. Типизированные события и снимки
для стандартных сообщений и необязательных сообщений ReGameDLL разбирают исходные
данные. `SayText` и `TextMsg` дополнительно требуют `chat.read`. `messages.read`
может раскрыть любые данные пользовательского сообщения, поэтому подписывайтесь
только на сообщения, нужные плагину.

Для регистрации синхронного фильтра отображения используйте
`set_filter(context,name,callback,user)` таблицы сообщений; null удаляет фильтр.
Требуются `messages.filter` **и** соответствующие разрешения на чтение.
Поддерживаются `SayText`, `TextMsg`, `ScreenFade` и `ScreenShake`.
Другие операции движка через этот интерфейс отменить нельзя.

Обработчик получает неизменяемый ввод и отдельный выходной буфер на 4 096 байт;
`*output_size` изначально содержит вместимость. Верните 0, чтобы сохранить данные,
1 — заменить (задайте длину результата), 2 — скрыть, -1 — сообщить об ошибке.
Фильтры идут в порядке загрузки; замена передаётся следующему фильтру, а решение
скрыть сообщение не отменяется последующими фильтрами. Вложенная обработка
сообщений пропускает синхронные фильтры, предотвращая рекурсивные цепочки.
Исходные обработчики вызываются не более одного раза. Некорректная замена
отключает нарушивший контракт плагин и сохраняет последние корректные данные.
ScreenFade должен занимать 10 байт, ScreenShake — 6; текстовые сообщения должны
укладываться в лимит, завершаться NUL и иметь корректный первый байт канала
или игрока. Не сохраняйте указатели на ввод. Перехватывайте исключения C++
и паники Rust внутри обработчиков; низкоуровневая регистрация фильтра в Rust
помечена unsafe, поскольку время жизни буферов и userdata контролирует плагин.

## Интерфейс под управлением хоста

`nextclient.ui` требует `ui.windows`. Для интерактивных окон и пунктов меню также
нужно `ui.input`. У элементов настроек и рисования HUD отдельные разрешения.
Пассивные окна работают в меню и игре без корректного предсказания. Хост управляет
панелями, освобождением ввода, прокруткой, текстурами и очисткой дескрипторов.

`create` принимает следующий объект и возвращает `handle`:

```json
{
  "title":{"en":"Statistics","ru":"Статистика"},
  "menu":{"en":"Statistics","ru":"Статистика"},
  "surface":"all", "interactive":true, "visible":false,
  "width":480, "height":360,
  "items":[
    {"id":"title","kind":"label","text":{"en":"Display","ru":"Отображение"}},
    {"id":"enabled","kind":"checkbox","text":{"en":"Enabled","ru":"Включено"},"value":true},
    {"id":"reset","kind":"button","text":{"en":"Reset","ru":"Сброс"}}
  ]
}
```

`surface` принимает `menu`, `game` или `all`; игровые окна показываются,
когда игровое меню закрыто. `menu` необязателен. Текстовые поля явно задают строки
`en` и `ru`. Другие типы элементов: `slider` (`min`, `max`, целочисленное `value`),
`text` (строковое `value` до 1 024 байт), `list` (массив локализованных подписей
`options`, выбранный целочисленный индекс `value`, -1 при отсутствии выбора)
и `image` (ID `texture`). Список содержит до 64 вариантов; открытие окна сохраняет
индекс -1 без выбора пункта и без события ввода. Значение ползунка должно лежать
между обеими границами, в том числе при полностью отрицательном диапазоне.
Элементы образуют прокручиваемые строки; необязательный
целочисленный `row` группирует элементы горизонтально в ячейки равной ширины.
Для подписи поля ввода добавьте элемент label в ту же строку. Допускается до восьми
окон и 64 элементов на окно. Escape или закрытие скрывают окно и освобождают
его ввод. Сбой или выгрузка удаляют окна и пункты меню.

`show` принимает `{"handle":N,"visible":true}`, `destroy` — `{"handle":N}`,
`update` — `{"handle":N,"window":{...complete creation object...}}`.
Обновление заменяет всё описание окна; объединяйте изменения вместо пересоздания
каждый кадр. `sdk.ui` содержит `handle`, `id` элемента и типизированное `value`
для изменений либо null для кнопки. `$open`/`$close` — действия видимости,
созданные хостом. Дескрипторы и действия элементов не дают доступа к окнам
другого плагина.

Необязательный `fonts` содержит до четырёх записей `{id,name,height,weight}`
для установленного шрифта Windows (высота 8–72, насыщенность 100–900).
Подписи, кнопки и флажки выбирают шрифт по ID `font`. Шрифты используют общий
ограниченный кеш процесса на 128 описаний; у VGUI нет API удаления шрифта.
Необязательный `textures` содержит до четырёх записей `{id,width,height,rgba}`
размером до 64×64 каждая с массивами байтов RGBA. Загрузка текстур учитывается
в лимите JSON создания/обновления 64 КиБ; текстуры освобождаются при уничтожении
окна. Указатели на объекты VGUI или рендерера не предоставляются. Сложные редакторы,
собственные файлы шрифтов и 3D-рендеринг не поддерживаются.

## Сервисы и пользовательские темы

`nextclient.services/register` во время загрузки принимает локальное `name`,
положительное целочисленное `version` и необязательный массив `permissions`
для вызывающей стороны. Полное имя сервиса — `<plugin-id>/<name>`.
`topic` регистрирует тему публикации с теми же полями. Публикация и регистрация
собственного сервиса не требуют разрешения; для использования чужого нужны
`services.call`, все разрешения из контракта поставщика и совместимый включённый
поставщик, явно указанный в `requires` вызывающего плагина. Разрешения поставщика
не наследуются. Поставщики отвечают за все выполняемые ими действия SDK
и должны проверять методы и данные согласно своему контракту.

`lookup`: `{name,version}` возвращает наличие совместимого сервиса или темы.
`request`: `{name,version,method,data}` возвращает ID `request`, затем доставляет
поставщику `sdk.service` с этим ID, `caller`, `name`, `version`, `method` и `data`.
`reply`: `{request,data}` может использоваться один раз и только этим поставщиком.
Вызывающая сторона получает `sdk.reply` с `request` и `result:{ok:true,data}`.
Ожидающие вызовы завершаются по тайм-ауту через 10 секунд и отменяются при сбое
или выгрузке поставщика с `result:{ok:false,error}`. Синхронных вызовов между
плагинами и заимствованных указателей на функции нет, что предотвращает рекурсию
стека и висячие указатели на функции DLL. Допускается не более 1 024 незакрытых
запросов и 1 024 регистраций всего. На плагин — 64 незакрытых запроса и 32
регистрации сервисов или тем. Лимиты включают ожидающие запросы и завершения,
для которых явно включено сохранение. На запрос резервируется 256 КиБ учётной ёмкости; общий бюджет может
ограничить число запросов раньше.

`subscribe`/`unsubscribe`: `{name,version}` для тем. `publish`: `{name,data}`
доступен только владельцу темы. Подписчики получают `sdk.topic` с `name`,
`version` и `data`. Разрешения, требуемые поставщиком, проверяются и для запросов
сервисов, и для подписок на темы и доставки сообщений. Уведомления используют
ограниченную очередь; доставка тем остаётся без гарантии.

Запросы версии 1 сохраняют исходное поведение: по умолчанию запись освобождается
после постановки `sdk.reply` в очередь, включая тайм-аут, отмену и остановку
поставщика. `ack` не требуется; дескриптор результата расширения по-прежнему
освобождается через `release_result`. Уведомление может потеряться при переполнении.

Добавьте `"retain_completion":true` в `request`, чтобы явно включить сохранение
завершения независимо от доставки уведомления. Используется тот же интерфейс версии 1:

- `status` с `{request}` возвращает `{ok:true,request,state:"pending"}` или
  `{ok:true,request,state:"complete",result:{ok:true,data}}` либо результат с ошибкой.
- `cancel` с `{request}` завершает ожидающий запрос ошибкой; поздний ответ отклоняется.
  Обработчики, ещё ожидающие в очереди поставщика, пропускаются после отмены или
  тайм-аута; уже переданные поставщику действия отменить нельзя.
- `ack` с `{request}` освобождает завершённую запись. Ожидающий запрос подтвердить
  нельзя; повторное чтение результата доступно до подтверждения.

Операции доступны только владельцу запроса. `status` и `cancel` также работают
для обычных ожидающих запросов; отмена возвращает результат один раз и освобождает
запись без включённого сохранения. После `sdk.overflow` проверьте ожидаемые ID
с включённым сохранением, даже если уведомление не пришло. Тайм-аут и остановка
поставщика создают такие же сохранённые терминальные записи. Они живут до `ack` или остановки вызывающего
плагина и не переживают перезапуск. Зависимый плагин, остановленный вместе с
обязательным поставщиком, теряет записи, поскольку его SDK-активность прекращена.

## Одобренные пакеты

Используйте `plugins/<directory>/plugin.dll` как точку входа, вспомогательные DLL
размещайте непосредственно рядом, ресурсы — в подкаталогах. Встроенный манифест —
единственный источник метаданных. Вспомогательные DLL не выполняются при обнаружении.
При одобрении хешируются пути и содержимое **всех** файлов; добавление, удаление
или изменение ресурса либо DLL требует повторного одобрения. Пока пакет загружен,
одобренные файлы заблокированы от записи и удаления. Лимиты пакета: 128 файлов,
64 МиБ на файл и 256 МиБ всего. Точки повторной обработки файловой системы
(reparse points), символические ссылки и DLL в подкаталогах запрещены.
Общий бюджет может отклонить чтение пакета раньше индивидуального лимита файла.

Импорты должны быть x86 и использовать простые имена DLL без пути. Задавайте
уникальные имена вспомогательных DLL, например `mycompany_imagecodec_v1.dll`:
Windows разрешает уже загруженные DLL по имени, поэтому отдельные каталоги
не изолируют пространства имён. Конфликт с именем загруженной DLL блокирует пакет.
Отложенные импорты, циклы и импорты обратно в DLL точки входа запрещены.
Хост предварительно загружает проверенные вспомогательные DLL в порядке импортов
и разрешает внешние импорты только из System32 или модулей, уже загруженных игрой.
Путь поиска DLL процесса не меняется. Нативный код плагина может самостоятельно
вызывать API ОС; разрешения SDK не являются песочницей.

`nextclient.package/read` принимает `{"path":"assets/config.json"}` и возвращает
`bytes` для уже одобренного файла размером не более 64 КиБ. Пути используют `/`,
отсчитываются от DLL точки входа и должны точно совпадать с одобренным файлом.
Произвольный доступ к файловой системе через этот интерфейс отсутствует.
Для изменяемых данных используйте отдельное хранилище плагина; изменение файлов
пакета сделает одобрение недействительным.
