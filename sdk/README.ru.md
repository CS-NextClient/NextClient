# SDK 1.0 для плагинов NextClient

Создавайте нативные **DLL для Windows 10+ x86** на Rust или C++. Оба SDK используют
единый версионируемый C ABI. Для проекта плагина не нужны исходники игры, HLSDK,
заголовки VGUI или собственный связующий код на C++. Для Rust нужны стандартный
компоновщик MSVC и инструменты Windows SDK, но исходный код плагина полностью
пишется на Rust. API 1 предоставляет разрешения, декларативные настройки,
консольные команды, копии игрового состояния, покадровые обработчики, квары,
управление видимостью HUD, рисование текста и прямоугольников, локальные звуки,
игровые события, чат, управление подключением и отдельное JSON-хранилище
для каждого плагина. Версии SDK, ABI и API: 1.0.0 / 1 / 1.

## Установка и доверие

Среда выполнения плагинов пока поддерживает только Windows. Сборки клиента для Linux
не включают плагины, их меню и перехватчики; загрузка DLL Windows в Linux не поддерживается.

Поместите DLL плагинов в `plugins/` рядом с `cstrike.exe`. Откройте **«Плагины»**
из главного меню или меню паузы. Ознакомьтесь с названием, указанным автором,
описанием, версией, предупреждениями SDK и правилами совместимости; включите
нужные плагины и задайте порядок загрузки.
**OK сохраняет изменения и перезапускает игру, только если изменён набор включённых
плагинов или их порядок**. Если изменений нет, кнопка недоступна. **«Отмена»**
отбрасывает несохранённые изменения. Некорректные зависимости, конфликты или
повторяющиеся ID не позволяют сохранить конфигурацию с включёнными плагинами.
Рекомендуемый порядок применяется отдельным действием; рекомендации не запрещают
сохранить порядок, заданный вручную.

При обнаружении плагинов считывается PE-секция `.nclmeta` без выполнения точек
входа DLL. Новые или изменённые DLL отключены до явного включения. При одобрении
сохраняются SHA-256 всего файла DLL, его имя и ID плагина. Хост повторно проверяет
хеш и держит файловый дескриптор, запрещающий запись и замену загруженной DLL.
Отключение и изменение порядка также вступают в силу только после перезапуска.

При первом включении открывается локализованное окно с названием плагина, автором
и всеми запрашиваемыми разрешениями. **«Разрешить и включить»** принимает все
запросы; **«Отмена»** оставляет плагин отключённым. Одобрение сохраняется только
после нажатия OK в менеджере. Ту же одобренную DLL можно отключить и снова включить
без повторного запроса. Обновление или замена DLL требует нового согласия.
Предоставленные разрешения сохраняются вместе с хешем; для одобрения они должны
быть явно записаны в профиле.

Нативные плагины имеют права процесса игры. Этот механизм фиксирует согласие,
но не создаёт песочницу и не проверяет подпись. Ошибка обработчика SDK отключает
плагин и плагины, для которых он является обязательной зависимостью; нативные сбои,
повреждение памяти и `panic=abort` всё ещё могут привести к падению игры. Для
восстановления запустите игру с **`-noplugins`**, чтобы не загружать плагины.
При следующем запуске уберите этот флаг, чтобы пользоваться ими снова.
Выгрузка без перезапуска не поддерживается.

Одобрения и порядок хранятся в `plugins/profile.json`, настройки — в
`plugins/settings.json`. Сохранение использует атомарную замену файла. Каталог
должен быть доступен для записи. Метаданные, авторство и сведения о совместимости
заявляет сам разработчик. Менеджер показывает статусы «Активен», «Отключён»,
«Ожидает перезапуска» или «Заблокирован». При несохранённых изменениях появляется
уведомление о перезапуске; отмена всех изменений убирает его. Технические сведения
о совместимости показываются только при проблеме или применимой рекомендации
по порядку загрузки.

## Разрешения

Отсутствие `permissions` означает, что дополнительные разрешения не запрашиваются.
Неизвестные или повторяющиеся названия разрешений блокируют загрузку. Хост проверяет
разрешение при каждом вызове API, требующем его; запись в `capabilities` сама
по себе разрешения не предоставляет.

| Разрешение | Что позволяет |
| --- | --- |
| `ui.settings` | Добавлять вкладки и элементы настроек на страницы плагина или встроенные страницы |
| `ui.draw` | Получать вызовы обработчика рисования во время игры и рисовать прямоугольники и текст |
| `ui.hide` | Скрывать HUD, прицел, здоровье, радар или уведомления об убийствах |
| `player.write` | Менять отправляемые нажатия кнопок, углы обзора и движение |
| `cvars.read` | Читать существующие консольные переменные и подписываться на изменения значений |
| `cvars.write` | Менять существующие консольные переменные |
| `audio.play` | Воспроизводить локальные WAV-звуки |
| `cvars.create` | Регистрировать консольные переменные в пространстве имён плагина |
| `chat.read` | Подписываться на полученные сообщения игрового чата |
| `chat.send` | Отправлять сообщения в общий или командный чат |
| `chat.print` | Показывать текст в локальном чате HUD без отправки на сервер |
| `connection.connect` | Подключаться к серверу, в том числе заменяя текущее подключение |
| `connection.disconnect` | Отключаться от текущего сервера |
| `messages.read` | Подписываться на необработанные сообщения сервера |
| `messages.filter` | Фильтровать поддерживаемые сообщения чата и экранных эффектов при наличии разрешений на чтение |
| `ui.windows` | Создавать окна, элементы управления, текстуры, шрифты и пункты меню под управлением хоста |
| `ui.input` | Получать ввод с клавиатуры и мыши в окнах плагина |
| `services.call` | Вызывать объявленные зависимости плагина и подписываться на их темы сообщений |

Без дополнительных разрешений доступны регистрация консольных команд и вывод
в консоль, собственные настройки плагина, отладочный журнал, покадровые обработчики,
снимки сеанса, игрока, сущностей и оружия, расширенные игровые данные, чтение
подключения, публичные игровые события, собственное JSON-хранилище, информация
об игроках, проекция на экран и измерение текста.
Все разрешения независимы: запись кваров не разрешает их чтение, а рисование
не разрешает скрывать HUD. При отказе вызов возвращает false/zero или ошибку/None
в Rust. Обработчики ввода могут наблюдать ввод без `player.write`, но их изменения
отбрасываются. SDK не предоставляет запись локального здоровья, инвентаря или
позиции. Разрешения нативных DLL регулируют доступ через SDK; они не изолируют
произвольный нативный код и не мешают DLL обходить SDK через API операционной системы.

## Rust

Скопируйте `examples/rust-events` в свой проект и направьте его зависимость по пути
на `sdk/rust` или собственную копию SDK. Из каталога примера выполните:

```powershell
rustup target add i686-pc-windows-msvc
cargo build --release
```

Включённый `.cargo/config.toml` выбирает x86 и статическую компоновку CRT.
Скопируйте `target/i686-pc-windows-msvc/release/nextclient_rust_events.dll` в `plugins/`.
Используйте `Plugin`, `Host`, `Control` и `export_plugin!`; полный код приведён
в примере. Зависимости из crates.io, bindgen, скрипт сборки и исходники C++ не нужны.
Оставьте `panic = "unwind"`, чтобы SDK мог перехватывать паники на границах обработчиков.

```rust
fn load(&mut self, host: &Host<'_>) -> Result {
    host.subscribe_event("player.health", true)?;
    host.register_command("status")
}
```

## C++

SDK состоит только из заголовков. Подключите `cpp/include/nextclient/plugin.hpp`,
унаследуйте класс от `nextclient::Plugin`, объявите `NC_MANIFEST(...)` и экспортируйте
плагин через `NC_PLUGIN(Type)`. Нужен C++17 или новее с включёнными исключениями.
Библиотека импорта хоста не требуется.

```powershell
cmake -S sdk/examples/cpp-life-stats -B build/plugin-example -A Win32 -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x86-windows-static
cmake --build build/plugin-example --config Release
```

Скопируйте полученный `life_stats.dll` в `plugins/`. `BUILD_ALL` включает этот пример
на C++ в пакет; до одобрения он отключён. Пример запрашивает только `chat.print`
и использует зависимость проекта `taocpp-json` для чтения данных событий.
Сам SDK состоит только из заголовков и не требует библиотеки JSON.

Life Stats выводит общий полученный урон, убийства и убийцу из сообщения о смерти
после гибели локального игрока или окончания раунда. При наличии данных указываются
оружие и смертельные попадания в голову. Вывод в консоль происходит сразу, строки
локального чата выводятся с интервалом. Другим игрокам ничего не отправляется.
См. [пример](examples/cpp-life-stats/README.ru.md).

## Настройки и обработчики

Регистрируйте вкладки и элементы управления только во время `load`. ID вкладок
ограничены их владельцем. Для вкладок и элементов нужно `ui.settings`. Целочисленные
настройки без интерфейса можно регистрировать через `register_setting(id, initial, min, max)`
без этого разрешения. Элемент управления автоматически регистрирует свою настройку;
при использовании отдельно зарегистрированной настройки должны совпадать начальное
значение и границы. `set_setting` сохраняет значение сразу и не вызывает
`setting_changed` рекурсивно. Он обращается только к зарегистрированным настройкам
вызывающего плагина. Закрытие настроек кнопкой «Отмена» не отменяет такую запись.
Элемент может размещаться на собственной вкладке плагина или во встроенном разделе:
`multiplayer`, `game`, `keyboard`, `mouse`, `audio`, `video`, `voice`, `miscellaneous`.
Встроенные вкладки получают разделы **«Стандартные / Плагины»**, а собственные вкладки
появляются на верхнем уровне. Прокрутка элементов и выпадающий список неуместившихся
вкладок позволяют пользоваться большими наборами настроек. Имена встроенных разделов
зарезервированы и не могут использоваться для собственных вкладок.

Поддерживаются флажки, целочисленные ползунки с границами, выпадающие списки
с индексами и кнопки действий. Подписи и пункты списков поддерживают английский
и русский языки с английским в качестве запасного. Варианты списка разделяются
переводами строк, индексация начинается с нуля. Настройки находятся в пространстве
имён ID плагина. Зарегистрируйте начальные значения, затем вызовите `setting`
во время загрузки. `setting_changed` вызывается после успешного сохранения через
«Применить» или OK в настройках. «Отмена» сохраняет уже записанные значения.
Кнопки действий выполняются сразу; «Отмена» не отменяет их результат.

`command` получает изменяемую копию выбранных полей отправляемой команды
и снимок игрока только для чтения. Обработчики выполняются после исходной обработки
ввода и инверсии мыши, в порядке загрузки плагинов. `CAN_JUMP` исключает лестницы,
глубокую воду, прыжки из воды, замороженных и мёртвых игроков, а также наблюдателей;
дополнительно проверяйте `VALID` и `ACTIVE`. Указатели движка и серверная физика
не доступны. При ошибке обработчика его изменения команды отбрасываются,
а плагин отключается до следующего запуска.

Регистрируйте консольную команду во время `load` через `register_command("inspect")`.
Её полное имя — `nc.<plugin-id>.inspect`; плагины не могут заменять существующие
команды движка или других плагинов. `console_command` получает локальный ID
и аргументы без имени команды. После сбоя плагина его команды перестают вызываться.
Регистрация может быть отложена до завершения инициализации клиента.
Локальные ID команд состоят из 1–48 строчных ASCII-букв, цифр, подчёркиваний
или дефисов; точки запрещены для однозначности пространств имён.

`player()` возвращает локальные здоровье, броню, ID оружия и битовую маску инвентаря,
позицию, скорость, углы и смещение обзора, FOV, тип движения, уровень воды и флаги
движения. `entity(index)` возвращает текущий клиентский снимок сущности, включая
модель, положение и ориентацию, скорость, границы, владельца, команду, последовательность
анимации и эффекты. Возвращаются только текущие сетевые сущности. Здоровье сущности
достоверно только при установленном `NC_ENTITY_HEALTH` / `ENTITY_HEALTH`
(сейчас — для локального игрока). `weapon(id)` возвращает локальные предсказанные
данные магазина, владения, флаги перезарядки и состояния, а также таймеры атаки
для ID оружия 1–63. Здоровье и инвентарь других игроков, не переданные сервером,
недоступны; поля команды и скорости отражают фактически полученные данные.
Указатели движка не предоставляются. Снимки недоступны до предсказания, после
сброса карты или без подключения. SDK не предоставляет API записи мира и сущностей.

`read_cvar` отличает отсутствующий или запрещённый квар от пустой строки. C ABI
использует буфер вызывающей стороны и возвращает требуемый размер в байтах,
включая NUL; короткие буферы очищаются, частичная строка не записывается.
`write_cvar` меняет существующий квар через функцию движка с сохранением её поведения.
Он не выполняет консольный текст и не создаёт квары. Изменения следуют правилам
сохранения движка и не отменяются автоматически при остановке плагина.

`hide_ui(element, true)` запрашивает скрытие одного элемента: `NC_UI_HUD`,
`NC_UI_CROSSHAIR`, `NC_UI_HEALTH`, `NC_UI_RADAR` или `NC_UI_DEATH_NOTICES`
(в Rust используются те же имена без `NC_UI_`). Health означает индикатор здоровья;
броня, боеприпасы и индикаторы урона управляются отдельно. Уведомления об убийствах
охватывают как классическое, так и собственное отображение.
Передайте false, чтобы отменить запрос этого плагина. Запросы активных плагинов
объединяются; один плагин не может отменить запрос другого. Сбой или завершение
работы снимает его запросы. Меню «Плагины» остаётся доступным.
Произвольные панели VGUI не предоставляются.

`draw` получает размеры экрана, время и состояние перерыва между картами после
обычного рисования HUD. Только внутри этого обработчика можно вызывать
`draw_rect(x, y, width, height, rgba)` с цветом `0xRRGGBBAA`.
`draw_text(x, y, text, rgb)` использует `0xRRGGBB` и консольный шрифт движка
без альфа-канала. Текст и прямоугольники сохраняют порядок вызовов; они накапливаются
до успешного завершения обработчика и отбрасываются при его ошибке.
`measure_text(text)` возвращает ширину и высоту текста тем же шрифтом без рисования
и без разрешения. Текст — одна строка до 1024 байт; табуляция и переводы строк
запрещены. Набор символов и кодировка зависят от шрифта движка. Окна под управлением
хоста поддерживают установленные шрифты и текстуры через
[интерфейс UI](EXTENSIONS.ru.md#интерфейс-под-управлением-хоста).
3D-рендеринг не предоставляется.

`frame(session)` вызывается один раз на кадр GameUI, включая кадры меню
без подключения. Разрешение не требуется. Когда клиентский мост подключён,
`session()` получает аналогичную копию состояния: флаги `CONNECTED`/`IN_GAME`,
максимум клиентов, размеры экрана, клиентское время, интервал кадра и путь карты
(например, `maps/de_dust2.bsp`). Интервал берётся из последней длительности кадра HUD,
равен нулю до первого такого кадра и ограничен диапазоном 0–1 секунды.
При отключении в снимках очищаются карта, клиентское время и максимум клиентов.
Снимки можно сохранять по значению. Для уведомлений о переходах подпишитесь
на `map.changed` и `connection.changed`.

`player_info(index)` возвращает копии имени, модели, пинга, потерь пакетов и флагов
локального игрока и наблюдателя для занятого слота. Перебирайте `1..=max_clients`;
пустые и отключённые слоты возвращают false/None. Имя, модель и карта представлены
массивами ограниченного размера с завершающим NUL; в Rust доступны методы
`name()`, `model()` и `map_name()`. `world_to_screen([x, y, z])` проецирует мировые
координаты в пиксели экрана через текущую камеру. Точки позади камеры дают false/None;
успешная проекция может оказаться за пределами экрана. Проекция наиболее полезна
внутри `draw`, после обновления камеры.

`play_sound("buttons/blip1.wav", 0.5)` требует `audio.play`. Пути отсчитываются
от игрового пути поиска `sound/`, используют прямые слеши, ASCII-буквы, цифры,
подчёркивания, дефисы или точки и должны заканчиваться на `.wav` (до 240 байт).
Абсолютные пути, пустые сегменты, сегменты `.` и `..`, неконечная громкость
и громкость вне диапазона 0–1 запрещены. Успешная отправка не гарантирует наличие
ресурса. Звук воспроизводится локально; команда серверу не отправляется,
ресурсы не устанавливаются.

`console_print("Ready")` не требует разрешения и не добавляет префикс с ID плагина.
Принимается до 4096 байт. Плагин сам задаёт видимую пользователю метку.
Поддерживаются цветовые байты `\x01` (по умолчанию), `\x03` (синий) и `\x04` (зелёный),
например `"\x04[Life Stats]\x01 Ready"`. Маркеры форматирования с процентами выводятся
как обычный текст и не выполняются как команды. В конце добавляется перевод строки.
Как и другие клиентские сервисы, вывод недоступен до подключения клиентского моста;
загруженный раньше плагин может повторить попытку из `frame`. Сообщения не ставятся
в очередь. `log()` — отладочный вывод без разрешения, не вывод в игровую консоль.
Произвольное выполнение консольных команд намеренно отсутствует, поскольку
позволило бы обойти отдельные разрешения на изменение кваров и ввода игрока.

Обработчики и обычные функции хоста выполняются в игровом потоке.
[Интерфейсы расширений](EXTENSIONS.ru.md) предоставляют асинхронное хранилище
и функцию отправки, безопасную для рабочих потоков. Из рабочих потоков можно
вызывать только эту функцию отправки. Не сохраняйте заимствованные указатели
и ссылки обработчиков и не используйте хост после завершения работы.
Скопированные снимки состояния можно сохранять.
Завершение выполняется в обратном порядке загрузки. Неудачная загрузка откатывает
регистрации и вызывает unload для очистки частичной инициализации. Дождитесь
завершения рабочих потоков во время unload. Исключения C++ и паники Rust не должны
пересекать границу ABI; высокоуровневые SDK перехватывают их.
Обработчики Rust получают заимствованный `Host`, доступный только на время вызова.
Операции хоста отклоняют вызовы из рабочих потоков и от отключённых из-за ошибки
плагинов. Дождитесь рабочих потоков во время unload; сервисы хоста в unload недоступны.

## События, полные данные клиента, действия движка и хранилище

Названия и данные событий, разделы игровых данных, доступность, ограничения
и правила разрешений приведены в [справочнике игрового API](game-api.ru.md).

- `subscribe_event(name, enabled)` доставляет именованные события JSON в `event(name, json)`.
- `game_data(section, index)` возвращает копию JSON с клиентским предсказанием,
  сетевым состоянием сущностей, определениями и предсказанием оружия, боеприпасами,
  таблицей счёта, состоянием матча/HUD и подключением. Доступны только данные,
  фактически полученные клиентом.
- `create_cvar(id, initial, archive)` регистрирует квар в пространстве имён плагина
  во время загрузки. `watch_cvar(name, enabled)` доставляет `cvar.changed`
  после фактических изменений.
- `send_chat(text, team)`, `connect(host, port)` и `disconnect()` используют
  отдельные разрешения. Чтение состояния подключения не требует разрешения.
- `store_get`, `store_set`, `store_delete` и `store_keys` сохраняют структурированный
  JSON в `plugins/data/plugin-<plugin-id>.json`. Вызовы всегда обращаются
  к хранилищу вызывающего плагина и не требуют разрешений. Настройки и это
  хранилище независимы.

`examples/rust-events` — пример полностью на Rust без запрашиваемых разрешений
и внешних крейтов. Он сохраняет счётчик запусков и последнее событие здоровья,
а также регистрирует `nc.org.nextclient.events.status` для вывода данных подключения.
Для сборки выполните в его каталоге `cargo build --release --locked`.
JSON передаётся строками UTF-8, поэтому автор плагина может выбрать свой парсер.

## Манифест и совместимость

Встройте один JSON-манифест в UTF-8 с завершающим NUL размером не более 64 КиБ
через макрос SDK. Экспортируемый статический объект сохраняет секцию
в оптимизированных Release DLL.

```json
{
  "schema": 1,
  "id": "com.example.movement",
  "name": "Movement tools",
  "author": "Example author",
  "description": "Adds movement preferences.",
  "translations": {
    "ru": {
      "name": "Инструменты движения",
      "description": "Добавляет настройки движения."
    }
  },
  "version": "1.2.0",
  "sdk": "1.0.0",
  "abi": 1,
  "api": 1,
  "capabilities": ["settings", "command"],
  "permissions": ["ui.settings", "player.write"],
  "compatibility_revision": 2,
  "requires": [{"id":"com.example.core","version":">=1.0.0 <2.0.0","reason":"Needs the core behavior"}],
  "conflicts": [{"id":"com.example.other_movement","version":"*","reason":"Changes the same input"}],
  "after": [{"id":"com.example.camera","version":"<2.0.0","reason":"Camera adjusts angles first"}],
  "before": []
}
```

ID состоят из строчных ASCII-букв, цифр, точек, дефисов и подчёркиваний
(1–96 символов). Версии имеют вид `major.minor.patch` без суффиксов предварительного
выпуска и сборки. Диапазоны поддерживают `*`, точную версию или разделённые пробелами
сравнения `=`, `<`, `<=`, `>`, `>=`, объединённые логическим И. Сокращения Cargo/npm
вроде `^`, `~` и `||` не принимаются. Массивы отношений и возможностей необязательны.
При изменении рекомендаций совместимости увеличивайте `compatibility_revision`.

`name` и `description` — обязательные запасные строки. Необязательный объект
`translations` сопоставляет языковые теги с переводами `name` и/или `description`.
Менеджер использует текущий язык интерфейса, затем его базовый язык (`ru-ru` → `ru`),
а при отсутствии или пустом переводе возвращается к исходному полю. Хост поставляется
с английскими и русскими ресурсами интерфейса. Теги состоят из строчных букв,
цифр и дефисов (1–16 символов); допускается до 32 языков. В каждом языке название
ограничено 128 байтами UTF-8, описание — 4096 байтами. Rust и C++ встраивают один
и тот же формат манифеста. Без переводов запасные строки используются во всех языках.

Обязательные зависимости должны быть включены, соответствовать диапазону версий
и загружаться раньше. Зависимости не включаются скрыто от пользователя. Циклы
обязательных зависимостей блокируют затронутые плагины и зависящие от них;
независимые плагины могут загрузиться. Конфликт блокирует оба плагина.
Рекомендации before/after применяются только к включённому плагину указанного
диапазона версий. Рекомендуемый порядок вычисляется устойчивой топологической
сортировкой. При цикле рекомендаций выводится сообщение, порядок не меняется.
Версионируемые сервисы и темы доступны через `nextclient.services`; вызывающая
сторона должна объявить их поставщиков в `requires`.

`sdk` указывает SDK, использованный автором при сборке. Другая версия SDK вызывает
предупреждение, если ABI/API совместимы. Неподдерживаемые схема, ABI, требуемый API,
возможность или архитектура блокируют загрузку. Хост поддерживает ABI 1/API 1
и возможности `settings` и `command`. Структуры используют значения фиксированной
разрядности, стандартную раскладку C и `cdecl` (`extern "C"` в Rust,
**не** `extern "system"`). Языковой ABI, контейнеры STL, исключения и объекты,
памятью которых владеет аллокатор, не пересекают границу. Новая раскладка требует
новой версии ABI. Строки копируются при регистрации.

Плагины могут быть самостоятельными DLL или пакетами. Точка входа пакета —
`plugins/<package>/plugin.dll`; вспомогательные DLL с уникальными именами размещаются
в том же каталоге, ресурсы — в подкаталогах. Одобрение охватывает каждый файл пакета.
Загрузчик блокирует одобренные файлы, проверяет импорты x86 и конфликты имён,
загружает вспомогательные DLL в порядке зависимостей без включения поиска
по каталогам. См. [правила пакетов и API расширений](EXTENSIONS.ru.md).

Ограничения: 256 обнаруженных DLL, 64 МиБ на DLL, 64 КиБ на манифест, 16 вкладок,
128 элементов управления и настроек, 32 консольные команды на плагин, а также
4096 операций рисования и 64 КиБ текста на один вызов обработчика рисования.
Для имён и строк действуют дополнительные границы, описанные в заголовках и парсере.

## Проверка

`plugin-tests` проверяет правила совместимости, метаданные, одобрение бинарных
файлов, блокировки файлов, безопасный режим, сохранение настроек, согласие
и разрешения, разрешённые и запрещённые вызовы API, отклонение вызовов из рабочих
потоков, фильтрацию и повторный вход в обработку событий, разбор протокола,
изоляцию и сохранность хранилищ, проверку чата и подключения, звуков и путей,
ошибки покадровых обработчиков, порядок рисования текста и прямоугольников
с откатом, а также обработчики настоящих DLL. Укажите в `NEXTCLIENT_RUST_EVENTS_DLL`
абсолютный путь собранного примера событий, чтобы проверить обработчики Rust
и сохранение данных между перезапусками. Запускайте модульные тесты SDK командой:

```powershell
cargo test --manifest-path sdk/rust/Cargo.toml --target i686-pc-windows-msvc
```

Процесс CI собирает примеры на C++ и Rust и запускает их интеграционные тесты.
