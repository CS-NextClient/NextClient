# Поставляемая коллекция масок

Набор изображений, который клиент везёт с собой, чтобы материал мог сослаться на
картинку, уже имеющуюся у игрока: её не надо докачивать, и она не расходует бюджеты
(`kMaxDocTextures` у документа модели, `max_textures` у серверной таблицы считают
**различные** файлы). Сервер, раздающий скины, платит только за собственный артворк.

Файлы лежат в `assets/cstrike/materials/` и попадают в игру штатной установкой ассетов
(цель `BUILD_ALL` копирует весь `assets/`). В материале путь пишется относительно
игрового каталога: `materials/masks/wear/even.png`.

## Обещание стабильности

Как только материал сослался на файл коллекции, содержимое этого файла становится частью
внешнего вида чужого контента. Отсюда правило, действующее с первой версии:

- **имена вечны** - файл нельзя переименовать и нельзя переложить в другую папку, потому
  что папка входит в путь;
- **содержимое не меняется** - исправление маски делается новым именем, а не новой
  версией старой;
- **коллекция только пополняется**.

Без этого обновление клиента молча меняло бы вид скинов на серверах.

Это же ограничивает и правки `make_masks.py`: менять можно генерацию тех файлов, которых
ещё нет, и добавлять новые. Перегенерация существующего файла с другим результатом -
нарушение правила, даже если новый вариант лучше.

## Состав

| Папка | Что там | Обычный вход |
| --- | --- | --- |
| `masks/wear/` | пороговые карты: в каком порядке поверхность сдаётся | `uWearMap` |
| `masks/noise/` | шумы нескольких частот и характеров | `uWearMap`, `uPattern` |
| `masks/scratches/` | царапины, тонкие и грубые, направленные и хаотичные | `uWearMap` |
| `masks/dirt/` | грязь, подтёки, разводы | `uWearMap` |
| `masks/reflect/` | где поверхность вообще ловит свет: белое блестит, чёрное нет | `uReflectMask` |
| `surfaces/` | что проступает из-под стёртого: металл, латунь, пластик | `uUnderlay` |
| `matcaps/` | отражение, разворачиваемое от точки обзора | `uSphereMap` |

Маски из `masks/reflect/` намеренно почти двоичные. Маска, отвечающая на вопрос «блестит или
нет», обязана на него отвечать: серое поле около одного значения просто ровно приглушает
эффект везде, а это то же самое, что маски нет. Картинка из `surfaces/` в этой роли не
работает по той же причине - у `metal_bare.png` красный канал лежит в 0.52..0.71.

Папки названы по смыслу, а не по параметру: коллекция должна пережить появление второй
программы с другими именами входов. Панель показывает папки разделами и ничего не знает
об их назначении.

## Соглашения

**Тёмное стирается раньше светлого.** Пороговая карта сравнивается с величиной износа
через `smoothstep`, поэтому царапина рисуется тёмной линией по светлому полю.

**Всё бесшовно.** Трансформы масок (`uWearMapTransform`, `uUnderlayTransform`,
`uPatternTransform`) тайлят картинку по собственным координатам модели, и шов был бы виден
на каждом повторе. Поля строятся периодическими, штрихи дорисовываются во все восемь
соседних тайлов.

**512x512.** Для порога и шума этого достаточно; клиентский потолок 1024 остаётся для
случаев, где он действительно нужен. Размер - это и вес поставки, и видеопамять на каждую
использованную маску.

**Маски серые, поверхности и matcap'ы цветные.** Шейдер читает у пороговой карты только
красный канал, так что хранить три одинаковых - лишний вес.

## Генерация

```bash
python tools/material_masks/make_masks.py
```

Скрипт детерминированный: каждая папка получает собственный сид, поэтому добавление папки
не сдвигает содержимое написанных раньше. Зависимости - `numpy` и `Pillow`, те же, что у
остальных скриптов в `tools/`.

Коллекция производится скриптом, а не собирается из принесённых откуда-то файлов: так она
воспроизводима, проверяема при ревью и не тянет за собой вопросов о происхождении и
правах.
